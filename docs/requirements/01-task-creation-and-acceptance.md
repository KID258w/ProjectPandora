# 需求 01：任务创建、审批与验收

## 文档信息

- 版本：1.5
- 状态：MVP 需求已确认
- 范围：创始人、部门经理、团队长、普通员工的任务创建、审批、执行与验收；部门经理可通过统一流程向其他部门经理派发任务
- 关联 OpenSpec：`task-dispatch-and-acceptance`、`cross-department-coordination`

## 1. 目标与核心规则

系统以一条具体、责任人明确的任务为管理对象，支持创建、直属上级审批、执行、提交成果和直接派发者验收。现实中的会议讨论与工作拆解不需要在系统中建模；系统不提供“拆分任务”操作，也不建立父子任务树。

任务之间如需说明来由，可填写可选的文字“关联说明”（例如“来源于季度产品规划”）。该说明仅用于阅读和追溯，不是任务关系，不产生父子层级、进度汇总、权限继承或取消级联。

普通任务的完成状态只有“未完成”和“已完成”。审批、待验收、退回、取消属于单独的流程记录，不扩展任务完成状态。任务不使用百分比进度，只保留带操作人和时间的文字更新记录。

## 2. 角色与创建范围

| 创建人 | 可创建给谁 | 审批人 |
|---|---|---|
| 创始人 | 公司全体成员（含本人、部门经理、团队长和普通员工） | 无需审批 |
| 部门经理 | 自己、本部门团队长，或其他部门经理 | 创始人 |
| 团队长 | 自己或本团队普通员工 | 所属部门经理 |
| 普通员工 | 仅自己 | 所属团队长 |

以上创建人均使用统一的“创建任务”表单。任务创建人和负责人是两个不同字段；负责人每项任务仅一人。创始人可从本公司已录入的全体成员中选择负责人，不受部门或汇报层级限制；部门经理可选择本人、本部门团队长或其他部门经理；团队长只能选择本人或本团队普通员工；普通员工只能选择本人。除创始人外，不可越级指派给其他组织中的团队长或普通员工，也不可指派给本公司以外的人员。

部门经理创建给本人或下属的普通任务，审批通过后进入“我创建的”；审批通过且负责人是本人时，同一条任务也进入“我的任务”。无需为了自己承担的工作额外建立物理子任务。

## 3. 任务字段与表单

### 3.1 创建任务表单

| 字段 | 规则 |
|---|---|
| 创建人 | 当前登录用户自动确定 |
| 负责人 | 必填；创始人可选择公司全体成员，其他角色只能选择本人或允许范围内的直属下级；每项任务一人 |
| 标题 | 必填 |
| 任务详情 | 必填 |
| 截止时间 | 必填 |
| 完成时需提交的材料 | 可选文字，说明预期交付物；不是在创建时上传实际成果 |
| 关联说明 | 可选纯文本，仅作说明，不建立任务间物理关联 |

任务优先级由执行人根据个人安排处理，不由创建人设置。任务不设百分比进度字段。

### 3.2 执行更新表单

执行人可为未完成任务追加文字更新说明。系统为每条说明记录提交人和时间，保留历史记录；不得要求或接受百分比进度。

### 3.3 完成提交表单

完成提交与任务创建是两个不同表单。执行人填写必需的完成说明；若创建人填写了预期提交材料，完成时须提供相应材料的文字说明或成果位置。MVP 不要求上传附件。若没有指定材料，完成说明即可提交。

## 4. 审批流程

只要创建人存在直属上级，其创建的任务无论分配给自己、下属还是其他部门经理，都必须先由直属上级审批。创始人是最高层，创始人创建的任务无需审批。部门经理 A 将普通任务分配给其他部门经理 B 时，仍由 A 的直属上级（创始人）审批。

审批有独立界面和独立流程状态：

- “待你审批”和“待上级审批”统一收纳在独立的“审批中心”，不作为普通任务中心的任务分类。
- 待审批任务在审批通过前只出现在创建人的审批中心“待上级审批”和审批人的审批中心“待你审批”；不出现在“我创建的”或负责人的“我的任务”。
- 审批通过后，任务出现在创建人的“我创建的”和负责人的“我的任务”。创始人创建的任务免审批，创建后直接出现在对应列表。
- 审批前，负责人不能在“我的任务”中看到或执行该任务。
- 审批退回必须填写原因。创建人可查看原因、修改任务并重新提交审批。
- 审批人仅限创建人的直属上级；更高层级的只读可见权不等于审批权。
- 审批通过后，若修改负责人、截止时间、任务详情或预期提交材料等关键定义，须重新经过直属上级审批。

普通任务送审不再要求接收人二次接受。创建与审批成功后自动进入负责人任务列表，完成后由直接派发者验收。

## 5. 任务入口与列表

### 5.1 普通任务中心

任务中心的核心列表为：

- **我的任务**：当前用户作为负责人的已审批任务；包括他人创建并分配给自己的任务（含其他部门经理派发的任务）和自己创建并分配给自己的任务。列表不按部门来源或跨部门属性分类。
- **我创建的**：当前用户创建且已通过审批（或创始人免审批）的任务，包括分配给自己和下属的任务。待审批及被退回待修改的任务不在此列表。
- **下属任务**：管理者按组织范围只读查看下属的已审批任务。筛选表单提供“承担的任务 / 创建的任务”范围，默认“承担的任务”；切换为“创建的任务”时按被选下属作为创建人筛选，显示其已审批的派发任务。

“我创建的”中的本人任务与“我的任务”中的本人任务读取同一任务记录。任务详情展示创建人和负责人信息，便于了解任务来由；不设置跨部门类型标记或专用筛选。

任务中心不再把“我的任务”“我创建的”“下属任务”显示为常驻分类标签。普通任务列表使用一个“筛选”入口打开筛选表单，按以下条件组合筛选：

- **任务范围**：“全部”“我的任务”“我创建的”。“全部”合并本人承担和本人创建的已审批任务，同一任务只显示一次。
- **截止日期**：可选起始日和结束日，筛选任务截止日期；任一端可留空，填写的日期边界均包含在结果中。默认不限制日期。
- **完成状态**：“全部”“未完成”“已完成”。默认全部；筛选只改变列表展示，不改变任务状态。

任务列表的筛选条件放在表单内，后续新增筛选条件也沿用该表单，不在列表页增加常驻筛选标签。默认进入“我的任务”，日期和完成状态均不限制。

“下属任务”和审批中心作为任务中心右上角的快捷入口；无权查看下属或没有审批队列权限的角色不显示相应入口。进入“下属任务”后同样通过“筛选”打开表单，包含任务范围、截止日期、完成状态，以及“查看对象”人员条件。任务范围为“承担的任务 / 创建的任务”，默认“承担的任务”；“承担的任务”按负责人筛选，“创建的任务”按创建人筛选。两种模式只显示已审批任务，待上级审批或被退回待修改的任务仍只在审批中心。默认查看“全部下属”，其余条件不限制。人员条件支持按员工姓名搜索，只能从当前用户组织层级内获准只读查看的下属（包括下属的下属）中选择；选择具体员工后，仅按该员工对应的承担人或创建人身份筛选。截止日期和完成状态对两种模式均生效。姓名搜索仅搜索授权员工姓名，不搜索任务标题或详情；筛选不得扩大既有只读权限范围。

派发目标选择与下属只读查看是两套按角色校验的人员范围：创建任务时严格使用第 2 节的负责人权限矩阵；“下属任务”的查看对象严格使用当前用户组织层级内的下属范围。两者不得因筛选或搜索互相扩大权限。例如，部门经理可以按规则向其他部门经理派发任务，但其他部门经理不因此成为其“下属任务”的可查看对象；创始人可向公司成员派发任务，也可按最高层级查看公司下属任务。

创建任务入口固定为普通任务列表右下角的圆形“＋”按钮，随列表滚动时保持在屏幕右下角；不再在任务列表底部放置“创建任务”按钮。审批中心、任务详情和创建/编辑表单不显示该浮动入口。审批中心仍是独立页面和独立审批流程，不显示普通任务筛选表单或任务完成状态筛选。

审批中心根据当前用户角色展示“待你审批”（直属下级创建、等待当前用户审批）和/或“待上级审批”（当前用户创建、等待直属上级审批或被退回待修改）的列表。审批中心按审批流程状态处理任务，不显示“未完成 / 已完成”筛选；任务的完成状态不代表审批状态。

### 5.2 审批中心

审批中心是独立于普通任务列表的页面入口。当前用户具有审批下属任务或提交任务等待上级审批的权限时显示入口；进入后按角色显示相应审批队列，无记录时显示空状态。审批通过、退回、修改重提均在该审批流程中处理，不将审批状态混入任务完成状态筛选。

### 5.3 首页任务通知

首页铃铛提醒当前用户有未读的任务通知：

- 直属下级创建的任务进入当前用户“待你审批”后，向当前用户产生审批通知。更高层级的只读查看者不因此收到审批通知。
- 其他用户创建并派发给当前用户的任务，在审批通过、进入当前用户“我的任务”后，向负责人产生新任务通知；审批通过前不向负责人显示或提醒该任务。
- 当前用户为创建人且负责人也是本人时，不作为“他人派发”通知；需要上级审批的任务仍按审批流程通知审批人。
- 铃铛有未读通知时显示红点。打开通知列表后，列表中当时的未读通知标记为已读；若之后有新通知，红点重新显示。
- 审批通知打开对应任务详情并保留审批权限校验；新任务通知打开任务详情。仅查看通知不改变任务审批、完成或验收状态。

## 6. 执行、提交与验收

审批通过后，任务自动进入负责人的“我的任务”，初始完成状态为“未完成”。负责人打开任务详情或开始处理时可记录首次开始时间。负责人可查看任务内容、截止时间、预期材料、关联说明，并追加文字更新记录。

执行人提交完成后，任务仍为“未完成”，形成待直接派发者验收的提交记录。直接派发者可以：

- **验收通过**：任务变为“已完成”，保留完成说明、提交材料说明和验收记录。
- **退回**：必须填写原因；任务继续为“未完成”，负责人可查看原因、继续处理并重新提交。

直接派发者是创建该任务并指定负责人的人。审批人与验收人职责分离；上级因层级关系能只读查看任务，不因此获得验收权。任务负责人等于创建人时，不进行自我验收，由本人标记完成；若其创建任务需上级审批，仍须先完成审批。

任务定义允许创建人/直接派发者在未完成时修改。审批通过后的关键定义变更须重新审批；已完成任务只读。每次变更记录操作人、时间和变更内容。

## 7. 取消与数据可见性

- 直接派发者可取消自己派发的未完成任务，必须填写原因；取消只作用于当前任务，任务记录保留并归档，不物理删除。
- 子任务树不存在，因此没有级联取消；取消一项任务不会改变其他任务，也不向上取消任何任务。
- MVP 不提供负责人单独接受/拒绝任务、完成提交撤回、已完成任务重开、独立延期申请。
- 创始人、部门经理、团队长可按组织层级向下只读查看下属及下属的下属已审批的任务；可在“承担的任务”和“创建的任务”间切换，默认查看承担任务。查看下属创建的任务不授予修改、审批、验收或取消权限。
- 任务列表中，审批人只审批直属下级创建的任务；直接派发者负责自己创建任务的完成验收。

## 8. 跨部门协作场景

跨部门协作沿用统一的“创建任务”表单和普通任务流程，不单独建立任务类型、创建入口、列表、筛选属性或接口：

1. 部门经理 A 在统一负责人选择框中选择其他部门的部门经理 B，填写普通任务信息并提交。
2. A 有直属上级，因此任务进入 A 的“待上级审批”和创始人的“待你审批”；创始人审批通过后，该任务进入 A 的“我创建的”和 B 的“我的任务”。B 无需额外接受。
3. 任务详情通过创建人、负责人及其部门信息保留协作上下文。A 只查看自己创建的任务和 B 提交的结果，不查看 B 部门的内部任务明细。
4. B 可亲自执行，也可通过统一“创建任务”流程为本人或本部门团队长创建其他任务；这些任务有各自的审批和任务记录，不与 A 创建的任务建立物理父子关联，也不对 A 展示。
5. B 提交成果后，由直接派发者 A 验收或填写原因退回。

此场景不增加跨部门标记。创始人可按既有层级规则只读查看下属承担或创建的已审批任务，并审批直属下级创建的任务；创始人不因审批或只读查看而成为负责人或验收人。

## 9. 验收示例

### 示例 1：部门经理创建并分配给团队长

- **假如** 林经理为团队长周晓创建一项有截止时间的任务
- **当** 林经理提交创建表单
- **那么** 任务进入林经理审批中心“待上级审批”和周总审批中心“待你审批”，林经理“我创建的”和周晓“我的任务”暂时看不到
- **当** 周总审批通过
- **那么** 任务进入林经理“我创建的”和周晓“我的任务”，周晓无需再次接受

### 示例 2：部门经理创建给自己

- **假如** 林经理为本人创建任务
- **当** 周总审批通过
- **那么** 同一条任务显示在林经理“我创建的”和“我的任务”；完成后由林经理本人标记完成，不进行自我验收

### 示例 3：普通员工创建个人任务

- **假如** 普通员工陈宁为本人创建任务
- **当** 陈宁提交任务
- **那么** 任务进入陈宁审批中心“待上级审批”和直属团队长审批中心“待你审批”；审批通过后进入陈宁“我的任务”和“我创建的”，陈宁不可将负责人改为他人

### 示例 4：审批退回

- **假如** 上级认为待审批任务需要修改
- **当** 上级填写退回原因并退回
- **那么** 创建人可见退回原因，任务回到审批中心“待上级审批”；未审批通过前负责人不可执行，任务不显示在“我创建的”

### 示例 5：文字关联不是父子关系

- **假如** 创建人将关联说明填写为“来源于季度规划会议”
- **当** 任务保存、更新或取消
- **那么** 系统仅展示该说明，不创建父任务，不计算关联任务进度，不级联取消其他任务

### 示例 6：向其他部门经理派发普通任务

- **假如** 产品部经理 A 使用统一“创建任务”入口，将普通任务指派给研发部经理 B
- **当** 创始人审批通过
- **那么** 任务从双方审批中心队列移除，进入 A“我创建的”和 B“我的任务”，B 无需额外接受；任务不增加类型标记，B 内部创建的工作不对 A 可见
- **当** B 提交完成说明和要求的成果
- **那么** 只有 A 可以验收或填写退回原因

### 示例 7：只有直接派发者可以验收或取消

- **假如** 上级可只读查看下属任务，但不是该任务创建人
- **当** 该上级尝试验收或取消任务
- **那么** 系统拒绝操作；任务数据保持不变

### 示例 8：创始人向公司任意层级成员派发

- **假如** 创始人选择另一部门的团队长或普通员工为负责人
- **当** 创始人提交任务
- **那么** 系统允许创建，任务无需审批，并直接进入创始人的“我创建的”和该负责人的“我的任务”；完成后由创始人验收

## 10. MVP 不包含

物理父子任务树、任务拆分专用操作、自动进度汇总、百分比进度、任务接收确认、多人共同负责人、附件上传、完成提交撤回、已完成任务重开、独立延期审批、取消级联。
