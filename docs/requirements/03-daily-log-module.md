# 需求 03：工作日志模块

## 文档信息

- 当前版本：`v0.7`
- 当前状态：MVP 边界已按团队讨论收敛，尚未提交甲方确认
- 所属阶段：Sprint 0——需求分析与产品设计
- 当前范围：移动端日志填写、提交、历史查询及管理者查看
- 关联需求：`01-task-creation-and-acceptance.md`、`02-home-four-panels.md`、`04-month-week-day-work-views.md`

## 1. 需求目标

日志模块用于记录、整理和收集员工每天的实际工作，供本人回顾，并供权限范围内的上级只读查看。

当前需求基线为：

1. 每名用户每天最多维护一篇工作日志。
2. 日志状态为“未填写、草稿、已提交”。
3. 日志提交后供权限范围内的管理者查看，但不进入验收流程。
4. 日志可以关联多个本人任务，但不会自动修改任务进度。
5. 首页展示当前用户最近十篇日志摘要，并与独立日志 Tab 读取同一组日志数据。

## 2. 设计原则

- 日志用于记录工作过程，不替代任务进度和任务验收。
- 日志只有提交，没有团队长或部门经理验收。
- 日志正文只能由作者本人填写和修改。
- 管理者可以沿组织层级向下筛选查看权限范围内直接及间接下属的已提交日志，但不能代替下属填写或修改。
- 草稿内容仅作者本人可见。
- 管理者只能查看已提交日志，不展示草稿、未提交状态或提交情况统计；没有已提交日志时，不说明是未填写还是草稿。
- 任务与日志的关联只在日志新增或编辑界面维护。
- 首页展示当前用户最近十篇日志摘要，并提供填写今日日志的快捷入口；完整功能集中在独立日志 Tab。

## 3. 页面结构

### 3.1 普通员工

```text
日志
└─ 我的日志
   ├─ 今日日志
   └─ 历史日志
```

### 3.2 团队长

```text
日志
├─ 我的日志（默认）
└─ 查看对象筛选：本人 / 本团队成员
```

### 3.3 部门经理

```text
日志
├─ 我的日志（默认）
└─ 查看对象筛选：本人 / 本部门团队长 / 本部门员工
```

部门经理进入日志 Tab 时默认查看本人的今日日志。需要了解下属工作时，通过查看对象筛选切换到本部门组织树中的团队或成员；切换后按日期查看该对象的已提交日志。界面应明确显示当前对象及所属团队，并提供清除筛选、返回本人日志的入口。

创始人进入日志 Tab 时默认查看本人的今日日志，并可以通过查看对象筛选切换到公司范围内成员，按日期查看其已提交日志。该范围与需求 04 的创始人工作视图权限一致。

管理者的筛选范围按组织树确定，包含其权限范围内的直接和间接下属；不能跨出授权组织范围。选择成员时应明确显示组织路径，清除筛选后返回默认页面。

## 4. 日志数据规则

### 4.1 每日唯一日志

同一用户在同一自然日最多存在一篇工作日志：

```text
用户 + 日志日期 = 唯一一篇 DailyLog
```

当用户当天尚未创建日志时，进入日志页面显示空白新增表单；保存后创建当天日志。再次进入时打开同一篇日志，不得重复创建第二篇。

### 4.2 系统记录信息

系统自动记录：

- 日志作者
- 所属团队
- 所属部门
- 日志日期
- 创建时间
- 最后更新时间
- 提交时间
- 当前状态

日志所属团队和部门用于权限判断和历史追溯，不需要用户每天手动选择。

## 5. 今日日志填写界面

建议界面结构：

```text
今日日志                         2026年9月23日
状态：草稿

今日完成 *
[填写今天实际完成的工作……]

关联任务
[＋ 选择任务]

问题与风险
[填写遇到的问题或需要协调的事项……]

明日计划
[填写下一步工作安排……]

[保存草稿]               [提交日志]
```

### 5.1 用户填写字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 日志日期 | 系统生成 | 默认为当天，不允许用户在今日表单中随意修改 |
| 今日完成 | 是 | 记录当天实际完成的工作 |
| 关联任务 | 否 | 可以关联多个当前用户本人的正式任务 |
| 问题与风险 | 否 | 记录阻塞、风险和需要协调的事项 |
| 明日计划 | 否 | 记录下一步工作安排 |

MVP 只支持文本日志，不支持附件。“今日完成”为唯一必填字段；关联任务、问题与风险、明日计划均为选填。

## 6. 日志状态

日志状态流转为：

```text
未填写 → 草稿 → 已提交
```

### 6.1 未填写

- 当天尚不存在日志记录。
- 首页最近日志列表不补充空白日期；若今天尚未填写，显示“填写今日日志”入口。
- 管理者查看该成员和日期时，不显示日志记录或提交状态，也不区分未填写和草稿。

### 6.2 草稿

- 用户已经开始填写并保存日志，但尚未提交。
- 草稿正文仅作者本人可见。
- 草稿不出现在首页最近日志列表中；作者可在日志 Tab 中查看并继续填写自己的草稿。
- 管理者不能看到草稿记录、正文或状态；草稿与未填写对管理者不可区分。

### 6.3 已提交

- 日志对权限范围内的管理者可见。
- 首页显示日志摘要和查看入口。
- 日志不需要团队长或部门经理验收。
- 管理者不能修改、删除或代替作者重新提交日志。

### 6.4 已提交日志的当天修改

作者可以在日志所属当天结束前修改已提交日志；日志日期结束后，日志内容只读：

- 修改后日志继续保持“已提交”。
- 管理者可以看到修改后的最新内容。
- 系统更新“最后更新时间”。
- 不增加撤回、重新提交或再次验收流程。
- 不保留历史版本，只记录最后更新时间。

MVP 不允许新建或补写过去日期的日志；历史日志只读。当天保存的草稿仅作者本人可见，过了日志日期后不能继续修改或补提交。

## 7. 日志填写与提交流程

```text
进入日志 Tab
      ↓
默认打开今日日志
      ↓
填写今日完成、问题与风险、明日计划
      ↓
按需选择关联任务
      ↓
   ┌──┴──────────┐
   ↓             ↓
保存草稿        提交日志
仅本人可见      管理者可见
```

提交日志时，系统校验“今日完成”字段。校验失败时不得提交，但允许用户继续保存草稿。

## 8. 日志与任务的关联

### 8.1 数据关系

```text
一篇日志可以关联多个任务
一个任务可以关联多篇不同日期的日志
```

### 8.2 关联规则

- 用户只能选择自己负责或执行的正式任务。
- 可以关联待开始、进行中以及当天完成的任务。
- 日志允许不关联任何任务，例如会议、培训等非任务型工作。
- 关联任务不会自动修改任务进度。
- 填写日志不强制要求更新任务进度。
- 更新任务进度不强制要求填写日志。
- 任务详情只读展示与其关联的日志。
- 任务页面不能新增、删除或修改日志关联。
- 个人学习计划和重复习惯暂不作为正式关联任务，相关内容可以直接写入日志正文。

### 8.3 任务选择界面

任务选择器应当优先展示：

- 当前正在进行的任务
- 当天开始的任务
- 当天完成的任务
- 被退回修改的任务

日志模块不提供日志全文、关键词、标签或历史记录搜索。已取消任务不能建立新的日志关联。

## 9. 历史日志

### 9.1 日历视图

历史日志可以通过日历展示每日状态：

```text
2026年9月

23  已提交
22  已提交
21  未填写
20  已提交
```

点击日期后查看对应日志详情。

### 9.2 历史列表

历史日志列表可以展示：

- 日志日期
- 日志摘要
- 当前状态
- 关联任务数量
- 最后更新时间

MVP 历史日志只支持按日期浏览，不提供搜索、关键词统计、标签筛选或 AI 分析。

## 10. 团队长查看本人及团队下属日志

团队长进入日志 Tab 时默认查看本人的今日日志。需要查看团队成员时，使用“查看对象”筛选选择本团队成员；筛选范围沿本团队组织树向下，包含直接及间接下属，不包含其他团队或部门。

选择团队或成员后，只列出该日期已提交的日志：

```text
团队日志                       9月23日

张三    已提交日志    18:20
王五    已提交日志    17:45
```

团队日志页面不显示提交状态统计或未提交成员名单；没有已提交日志时只显示空列表，不说明成员是否填写或保存了草稿。查看成员时应显示组织路径，并提供清除筛选、返回本人日志的入口。

团队长可以：

- 切换日志日期
- 按日期、团队或成员筛选已提交日志
- 点击查看员工已提交日志
- 查看日志关联的任务
- 按成员筛选历史日志

团队长不能：

- 查看员工草稿记录、草稿状态或提交情况统计
- 查看员工草稿正文
- 修改或删除员工日志
- 代替员工提交日志
- 将员工日志直接改为已提交
- 对员工日志执行任务式验收

## 11. 部门经理查看本人及下属日志

部门经理的日志界面默认显示本人日志，不默认铺开部门成员列表或团队日志统计。需要查看下属时，部门经理通过筛选沿“本部门 → 团队 → 成员”的组织层级选择对象；范围包括本部门团队长及其下属员工等所有间接下属，不包含其他部门：

```text
日志                              9月23日
查看对象：[本人 ▼]

今日日志 / 历史日志
```

筛选到本部门成员后，可按团队或成员查看已提交日志：

```text
查看对象：[移动端团队 ▼]

张团队长    已提交日志    18:20
员工甲      已提交日志    17:45
```

部门经理的查看范围仅限本人所属部门组织树中的团队长、普通员工及其他层级的间接下属，不包含其他部门。筛选状态下应明确显示组织路径、目标团队或成员，并提供“清除筛选 / 返回本人”操作。页面只列出已提交日志，不显示提交状态统计、未提交成员名单或草稿相关信息。

部门经理可以：

- 默认查看自己的今日日志和历史日志
- 按日期、团队或成员筛选已提交日志
- 只读查看权限范围内直接及间接下属的已提交日志和任务关联

部门经理不能：

- 查看任何成员的草稿正文
- 查看草稿记录、草稿状态或提交情况统计
- 修改或删除下属日志
- 代替下属填写或提交日志
- 对下属日志执行任务式验收
- 通过日志界面访问其他部门成员的日志

日志界面只提供查看，不提供评论、退回、要求补充或修改操作。此处的下属筛选不改变需求 01 中的任务派发与验收权限，也不代表部门经理可以在任务模块逐层查看员工任务树。

## 12. 为什么日志不设置验收

任务模块已经存在正式验收链：

```text
普通员工任务 → 团队长验收
团队长任务   → 部门经理验收
```

日志的职责是记录工作过程。如果再次增加“日志提交—验收—退回修改”，会使员工每天同时面对任务验收和日志验收，增加不必要的操作负担。

因此当前规则为：

> 日志只有提交，没有验收；管理者负责查看和了解工作情况，不负责批准日志。

MVP 中管理者只读查看授权范围内的已提交日志，不提供评论、退回、要求补充、提醒补充或修改日志的操作。

## 13. 与首页“最近10篇日志”的关系

```text
首页“最近10篇日志”
→ 按日志日期从新到旧展示当前用户最多十篇已提交日志摘要
→ 提供填写今日日志的快捷入口

独立日志 Tab
→ 负责填写、提交、历史查询和下属日志查看
```

点击规则：

- 首页“填写今日日志”：进入日志 Tab 并打开当天新增或编辑页面。
- 首页点击已提交日志摘要：进入日志 Tab 并打开对应日期的详情。
- 直接点击底部“日志”：进入日志 Tab，默认打开当天日志。

用户提交日志后，首页应当立即更新最近日志列表并按日期重新排列；修改已提交日志后，对应摘要同步更新。保存草稿不影响首页最近日志列表。首页日志面板只展示当前登录用户自己的已提交日志；下属日志需从独立日志 Tab 按权限查看。

## 14. 权限汇总

| 操作 | 普通员工 | 团队长 | 部门经理 | 创始人 |
| --- | ---: | ---: | ---: | ---: |
| 填写和修改自己的日志 | 可以 | 可以 | 可以 | 可以 |
| 查看自己的历史日志 | 可以 | 可以 | 可以 | 可以 |
| 筛选查看权限范围内直接及间接下属的已提交日志 | 不可以 | 可以（本团队组织树） | 可以（本部门组织树） | 可以（全公司组织树） |
| 查看下属草稿、未提交状态或提交情况统计 | 不可以 | 不可以 | 不可以 | 不可以 |
| 修改下属日志 | 不可以 | 不可以 | 不可以 | 不可以 |
| 代替下属提交日志 | 不可以 | 不可以 | 不可以 | 不可以 |
| 验收下属日志 | 不支持 | 不支持 | 不支持 | 不支持 |

管理员不具备查看员工日志的 Web 入口；Web 管理端不提供日志查询功能，详见需求 05。创始人、部门经理和团队长仍按本模块及其业务权限，在移动端 App 查看授权范围内已提交的日志。

## 15. 初步验收场景

### 场景 1：用户首次填写今日日志

- **假如** 当前用户当天尚未创建日志
- **当** 用户进入日志 Tab
- **那么** 系统打开当天的空白日志表单，并且同一天不能创建第二篇日志

### 场景 2：用户保存草稿

- **假如** 用户已经填写部分日志内容
- **当** 用户选择“保存草稿”
- **那么** 系统保存当天日志并将状态设为“草稿”，草稿正文仅用户本人可见

### 场景 3：用户提交完整日志

- **假如** 用户已经填写所有必填字段
- **当** 用户选择“提交日志”
- **那么** 系统将状态设为“已提交”，记录提交时间，并允许权限范围内的管理者查看

### 场景 4：缺少必填内容时提交

- **假如** 用户尚未填写“今日完成”等必填字段
- **当** 用户尝试提交日志
- **那么** 系统拒绝提交并提示缺少的内容，但允许用户保存草稿

### 场景 5：一篇日志关联多个任务

- **假如** 用户当天推进了多项本人任务
- **当** 用户在日志编辑页面选择多个任务并保存
- **那么** 日志与所选任务建立关联，并在各任务详情中只读展示

### 场景 6：保存日志不改变任务进度

- **假如** 用户的日志关联了一项进行中的任务
- **当** 用户保存或提交日志
- **那么** 系统不自动修改该任务的进度和状态

### 场景 7：不关联任务的日志

- **假如** 用户当天只参加了会议或培训
- **当** 用户填写日志但不选择任何任务并提交
- **那么** 系统允许提交该日志

### 场景 8：团队长查看本团队成员已提交日志

- **假如** 本团队组织范围内的员工已经提交当天日志
- **当** 团队长在“查看对象”筛选中选择该员工
- **那么** 系统展示员工已提交的完整日志和关联任务

### 场景 9：团队长查看员工草稿

- **假如** 本团队员工的当天日志仍为草稿
- **当** 团队长筛选该员工和日期
- **那么** 系统不显示该草稿或提交状态；结果与该日期没有日志相同

### 场景 10：部门经理筛选查看本部门员工日志

- **假如** 本部门普通员工已经提交日志
- **当** 部门经理在日志界面将查看对象筛选为该员工
- **那么** 系统允许部门经理只读查看日志内容及关联任务

### 场景 11：管理者默认查看本人日志

- **假如** 当前用户是团队长、部门经理或创始人
- **当** 该用户首次进入日志 Tab 或清除下属筛选
- **那么** 系统默认显示该用户本人的今日日志，不自动显示下属日志正文

### 场景 12：管理者尝试修改下属日志

- **假如** 当前用户是日志作者的团队长或部门经理
- **当** 该用户尝试修改、删除或代替作者提交日志
- **那么** 系统拒绝操作，并且不产生任何日志数据变更

### 场景 13：作者当天修改已提交日志

- **假如** 用户当天已经提交日志
- **当** 用户在当天再次编辑并保存日志
- **那么** 日志继续保持“已提交”，系统更新最后更新时间，管理者可以查看最新内容

### 场景 14：日志日期结束后不可修改

- **假如** 用户的日志日期已经结束
- **当** 用户尝试修改已提交日志或继续编辑、提交草稿
- **那么** 系统拒绝修改或提交，日志内容保持不变

### 场景 15：首页打开日志编辑

- **假如** 当前用户当天尚未填写日志或日志处于草稿状态
- **当** 用户在首页点击“填写今日日志”
- **那么** 系统进入日志 Tab 并打开当天日志的新增或编辑页面

### 场景 16：日志更新后同步首页

- **假如** 用户已经在日志 Tab 提交当天日志，或修改了已提交日志
- **当** 用户返回首页
- **那么** 首页最近日志列表展示该日志的最新摘要，并按日期从新到旧排序；保存草稿不会将草稿显示在首页

### 场景 17：越权查看其他组织日志

- **假如** 当前用户是团队长或部门经理
- **当** 该用户尝试查看权限范围之外团队或部门成员的日志
- **那么** 系统拒绝访问且不返回日志正文

### 场景 18：管理者筛选查看间接下属日志

- **假如** 部门经理所属部门的一名普通员工是其下属团队长的下属，并已提交日志
- **当** 部门经理沿“本部门 → 团队 → 员工”筛选到该员工
- **那么** 系统允许部门经理只读查看该员工已提交日志及其任务关联，但不展示草稿或其他部门成员日志

### 场景 19：创始人筛选查看公司成员日志

- **假如** 公司范围内任一成员已提交日志
- **当** 创始人从本人切换筛选到该成员
- **那么** 系统允许创始人只读查看该成员已提交日志及其任务关联，不展示草稿

### 场景 20：管理者尝试评论或要求补充日志

- **假如** 管理者正在查看权限范围内下属的已提交日志
- **当** 管理者尝试评论、退回或要求补充
- **那么** 日志模块不提供这些操作，日志内容和状态保持不变

## 16. 已敲定的 MVP 边界

- “今日完成”必填；关联任务、问题与风险、明日计划选填。
- 日志只支持文本，不支持附件；历史日志只按日期浏览，不提供搜索。
- 作者只能在日志所属当天结束前修改或提交；MVP 不补写过去日期的日志。
- 不保留历史版本；日志日期结束后只读。
- 管理者只查看权限范围内已提交日志，不显示草稿、未提交状态或提交情况统计；不提供评论、退回、催补或编辑。
- 月、周、日“视图”Tab 不读取或展示日志内容，具体规则见需求 04。
