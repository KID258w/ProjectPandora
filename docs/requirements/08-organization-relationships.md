# 需求 08：组织关系

## 文档信息

- 当前版本：v1.2
- 当前状态：所有 App 用户可浏览公司组织关系；成员资料仅展示头像、姓名、手机号、职位、部门和团队
- 当前范围：Android App 公司组织树、成员只读资料，以及在既有权限范围内进入成员任务和日志
- 关联需求：`01-task-creation-and-acceptance.md`、`03-daily-log-module.md`、`04-month-week-day-work-views.md`

## 1. 入口与角色

“视图”页面右上角放置“任务中心”按钮。所有已登录的 App 用户都可在其旁边看到“组织关系”按钮，包括创始人、部门经理、团队长和普通员工。进入任务中心后，具有审批队列权限的用户在右上角看到“审批中心”按钮。Web 管理员不使用业务 App，不适用本入口。

组织关系页用于让全体 App 用户浏览公司人员层级和成员资料。资料页不提供组织、身份、账号或人员资料修改功能；人员变更仍由 Web 管理端处理。查看组织资料不会自动获得查看该成员任务或日志的权限。

## 2. 组织树

- 所有 App 用户看到同一份公司组织树：创始人节点与公司所有启用部门并列显示。部门默认折叠；展开部门后显示部门经理和下属团队；展开团队后显示团队长及团队成员。
- 如果公司当前没有启用的创始人，组织树从各启用部门开始展示。
- 组织树显示当前启用的业务成员和启用的部门、团队。停用成员、部门和团队不出现在此浏览树中；其数据仍由后端管理端按既有规则维护。
- 成员节点显示已上传的头像；没有头像时显示姓名首字。成员姓名右侧展示其业务职级：创始人、部门经理、团队长或员工。部门和团队节点显示对应名称。
- 顶部搜索栏按成员姓名或业务职级搜索全公司人员。输入关键词后切换为平铺的匹配人员列表，不展示部门/团队树；每条结果左侧显示头像、姓名及其部门/团队，右侧显示职位。创始人不显示部门/团队。清空关键词后恢复组织树。
- 点击成员打开该成员的只读资料页。部门、团队节点仅用于展开和收起，不打开人员资料。

## 3. 成员资料与工作入口

所有 App 用户均可打开组织树中任一成员的资料页。页面简洁展示成员头像和姓名，下面显示手机号，再列出职位、部门和团队。资料页不显示身份证号、直属上级或账号状态；完整身份证号也不会通过该接口返回。不得提供编辑、启停、改密或代改资料操作。

只有当当前 App 用户依据既有任务、日志权限可以查看该成员的下属工作时，资料页才显示以下入口；其他成员资料页不显示任务和日志入口：

- **查看任务**：进入该成员的下属任务列表，默认查看其承担的已审批任务；可切换为查看其创建的已审批任务，并按预计开始日期、截止日期和完成状态筛选。列表与任务详情均为只读，不能审批、编辑、验收或取消。
- **查看日志**：进入该成员的日志日历及日期详情，只返回已提交日志，不显示草稿、未提交状态或提交情况统计；不提供编辑、提交或删除操作。

是否显示入口由后端成员资料接口的 `can_view_tasks`、`can_view_logs` 分别告知 App；任务和日志接口仍分别进行既有权限校验。浏览全公司组织树或成员资料不会扩大任务、日志或工作视图的访问范围。

通过资料页进入任务或日志后，页面显示当前查看成员，并可返回该成员资料页。日志 Tab 默认仍打开当前用户自己的日志；它不再提供另一个下属选择器。任务中心默认仍打开当前用户自己的任务；下属任务由有相应查看权限的成员资料页进入。

## 4. 搜索、加载与空状态

- 初次打开时显示创始人和各启用部门；展开部门或团队后显示其下级节点，不把全体员工平铺在首屏。
- 搜索无匹配人员时显示明确空状态。
- 组织树或资料加载失败时显示错误和重试入口；搜索始终限定在公司组织树内。
- 若没有启用创始人，仍展示公司启用部门；若公司没有可展示的成员或组织节点，则显示空状态。

## 5. 与既有权限的关系

组织关系复用现有 User、Department、Team、manager 关系，不建立新的人员或组织实体，不改变身份、部门、团队、直属上级和启用状态规则。所有 App 用户可读取全公司启用组织树和成员只读资料。头像从当前成员数据库记录中读取；资料接口提供完整手机号，不返回身份证号。

组织资料页不改变既有日志、任务和工作视图授权。进入某成员的任务或日志仍须由服务端按原有规则验证；只有原本可查看该成员下属工作的用户才能看到相应快捷入口。客户端隐藏入口不代替服务端权限控制。Web 管理员仍不得调用业务 App 组织接口。

## 6. 验收场景

### 场景 1：所有 App 用户打开组织关系

- **假如** 当前用户是创始人、部门经理、团队长或普通员工
- **当** 用户打开“视图”页面
- **那么** 页面右上角显示“组织关系”；进入后可浏览公司创始人、启用部门、团队和成员

### 场景 2：按姓名或职级搜索

- **假如** App 用户位于组织关系页
- **当** 用户输入某位成员的姓名或职级
- **那么** 页面定位匹配成员并保留组织路径；搜索范围为全公司启用组织和成员

### 场景 3：查看成员资料

- **假如** 成员位于公司组织树内
- **当** 任一 App 用户点击该成员
- **那么** App 显示成员头像和姓名、手机号、职位、部门和团队，不显示身份证号，也不提供修改操作

### 场景 4：有权用户从成员资料进入任务

- **假如** 当前用户依据既有权限可查看该成员的下属任务
- **当** 用户点击资料页中的“查看任务”
- **那么** App 默认显示该成员承担的已审批任务，允许切换查看其创建的已审批任务，任务及详情均只读

### 场景 5：有权用户从成员资料进入日志

- **假如** 当前用户依据既有权限可查看该成员的下属日志
- **当** 用户点击资料页中的“查看日志”并选择日期
- **那么** App 只显示该成员已提交日志，不显示草稿或提交情况

### 场景 6：组织浏览不扩大工作数据权限

- **假如** App 用户可以查看某成员的组织资料，但没有查看其任务或日志的既有权限
- **当** 用户打开该成员的资料页
- **那么** App 不显示“查看任务”和“查看日志”入口；直接调用相应接口仍由服务端拒绝

### 场景 7：管理员不能通过业务 App 查看人员资料

- **假如** 当前用户是 Web 系统管理员而不是业务 App 用户
- **当** 用户请求组织关系或成员资料接口
- **那么** 服务端拒绝请求
