# 需求 02：首页四大信息面板

## 文档信息

- 当前版本：`v0.7`
- 当前状态：已按甲方最新确认更新首页摘要条数、二级列表和任务排序交互
- 所属阶段：Sprint 0——需求分析与产品设计
- 当前范围：移动端首页四大信息面板，其中任务面板读取当前用户的任务列表
- 关联需求：`01-task-creation-and-acceptance.md`

## 1. 需求目标

移动端首页通过四个信息面板，为用户提供从公司层面到个人层面的工作信息概览：

```text
公司发生了什么
      ↓
我当前有哪些重要任务
      ↓
我如何安排这些任务的重点顺序
      ↓
我最近记录了什么工作
```

对应四个面板：

```text
┌──────────────────┬──────────────────┐
│ 公司十大重要事项   │ 公司十大重要任务   │
├──────────────────┼──────────────────┤
│ 个人十大重点工作   │ 最近日志           │
└──────────────────┴──────────────────┘
```

首页四张卡片均最多预览 5 条，减少首页纵向占用；“十大”列表的二级界面仍最多展示 10 条，不足时按实际数量展示。“公司十大重要任务”由系统从当前用户未完成任务中按来源顺序选出；“个人十大重点工作”由用户从本人未完成任务中独立选择和排序；首页日志卡片展示最近 5 篇日志摘要。

## 2. 通用设计原则

四个面板遵守以下共同规则：

- 首页只展示摘要，不在首页承载完整业务操作。
- 点击摘要后进入对应模块的详情页面。
- 首页数据来自公司重要事项、当前用户任务和日志模块，不单独复制业务数据。
- “公司十大重要事项”面向所有移动端用户展示；任务和日志面板按当前登录用户展示各自的数据。
- 个人级内容只展示当前登录用户本人的信息。
- 团队长、部门经理和创始人在首页看到的任务与日志仍然是本人相关内容，不自动替换为下属内容。
- 下属任务和下属日志通过团队任务、部门任务或日志管理入口查看。

## 3. 公司十大重要事项

### 3.1 面板定位

“公司十大重要事项”回答：

> 公司最近发生了什么重要事情？

内容主要包括公司信息、重大事件、重要成果和里程碑，例如：

- 公司完成融资
- 与重要客户达成合作
- 新产品正式上线
- 重大项目通过验收
- 公司组织架构调整
- 公司获得重要奖项

### 3.2 内容产生与维护

```text
公司管理层确定公开内容
        ↓
管理员在 Web 端录入和维护
        ↓
发布到移动端首页
        ↓
所有移动端用户查看
```

管理员可以：

- 新增重要事项
- 编辑事项内容
- 手动设置首页展示顺序
- 发布或下架事项
- 管理相关图片和附件

公司重要事项不设“置顶”机制；首页展示顺序由管理员手动排序决定。

普通移动端用户只能查看，不能新增、修改或删除公司重要事项。

### 3.3 建议字段

公司重要事项至少包含：

- 必填：事项标题、内容摘要、完整正文
- 系统记录：发布时间、发布人
- 管理员维护：首页展示顺序、发布状态
- 选填：相关图片或附件

### 3.4 首页与详情展示

首页卡片最多显示管理员排序靠前的 5 条摘要，包括：

- 排名或顺序
- 事项标题
- 发布时间
- 简短摘要

点击卡片中的“查看全部”进入公司重要事项二级界面，最多展示 10 条事项的完整信息；点击某条事项可查看完整正文和相关附件。事项数量少于 10 条时按实际数量展示。

公司重要事项不是任务，因此不包含：

- 任务负责人
- 任务进度
- 父子任务
- 提交与验收
- 任务派发

## 4. 公司十大重要任务

### 4.1 面板定位

虽然面板名称保留“公司十大重要任务”，但它不是对所有用户相同的公司级任务榜单，而是**系统按任务来源优先级从当前登录用户的任务中选出的前十项**。它回答：

> 我的任务中，哪些上级分配、本级和跨部门任务会被系统列入前十？

不同用户看到的内容可以不同。普通员工看到分配给自己的任务；创始人、部门经理和团队长还可以看到自己创建并由自己负责的任务。管理者派发给下属的子任务，不会仅因派发者身份进入其本人任务面板；按需求 01 保留在本人“我的任务”中的根任务仍属于本人任务。

### 4.2 数据来源与生成规则

```text
当前用户的“我的任务”
        ↓
合并本人任务，并先按来源、再按状态排序
        ↓
自动截取前十项（不足十项则按实际数量展示）
        ↓
最多十项候选组成“公司十大重要任务”列表；首页卡片只预览其中前 5 项
```

- 面板直接读取需求 01 中当前用户的任务，不创建第二份任务数据。
- 默认来源顺序为：上级分配任务优先，其次本级任务，最后跨部门工作；该来源顺序是第一排序条件。
- 任务状态只有“未完成”和“已完成”两种；候选任务均为未完成，因此同一来源内按截止时间从早到晚排列，截止时间相同时按任务创建时间从早到晚排列。
- 已完成任务不进入候选列表。
- 取消归档任务不进入候选列表；级联取消归档的未完成后代任务同样排除。
- 系统自动选取前十项；用户不能在此面板中新增、删除、置顶或调整顺序。
- 任务列表变化后，面板内容随之更新。
- 用户点击某项后进入原任务详情，并按需求 01 中的权限操作。
- 面板展示任务标题、当前状态和截止时间，不显示进度百分比；不在首页另行编辑任务内容或状态。

### 4.3 各角色的任务来源

| 当前用户角色 | 可进入该用户任务列表的本人任务 |
| --- | --- |
| 普通员工 | 上级分配给本人的任务 |
| 团队长 | 上级分配给本人的任务、团队独立任务中由本人负责的任务、分配给本人的子任务 |
| 部门经理 | 创始人分配给本人的任务、部门自主任务中由本人负责的任务、分配给本人的子任务，以及已接受并由本人负责的跨部门工作 |
| 创始人 | 本人创建并负责的公司级任务、分配给本人的子任务 |

管理者创建任务并分配给下属时，只有本人同时承担了明确的执行子任务，该子任务才进入本人的任务列表；单纯作为派发者或管理者不等于本人负责执行。

### 4.4 展示与维护边界

- 系统列表先按“上级分配 → 本级任务 → 跨部门工作”的来源顺序，再按各来源内部的截止时间、创建时间排序，生成最多十项。候选项均为“未完成”，已完成及已取消归档任务排除。首页卡片仅预览该列表前 5 项，用户不能修改此面板的内容和顺序。
- 点击首页卡片“查看全部”进入公司十大重要任务二级界面，可查看最多十项任务；点击其中一项进入对应任务详情。任务本身的修改权限仍由需求 01 控制。
- 本面板显示的是个人任务，不展示全公司任务总榜、其他部门的任务或下属任务明细。
- “十大”表示最多十项，不足十项时不补充个人习惯或其他非任务内容。

## 5. 个人十大重点工作

### 5.1 面板定位

“个人十大重点工作”回答：

> 在我当前的未完成任务中，哪些是我自己选定的重点，先后顺序如何安排？

个人十大重点工作是用户自己从本人“我的任务”中的未完成任务挑选和安排的前十项。它与“公司十大重要任务”没有固定的任务集合关系：用户可以选择公司十大中没有显示、但仍存在于本人“我的任务”里的未完成任务。

```text
公司十大重要任务：系统按来源顺序从本人任务列表中自动取前十；首页预览前五
个人十大重点工作：用户从本人未完成任务中自行选择并排序，最多十项；首页预览前五
```

### 5.2 可调整范围

- 首次使用时，系统用“公司十大重要任务”中的未完成任务预填个人重点列表；之后用户可以从本人“我的任务”的未完成任务中选择或移出任务，并调整顺序，最多保留十项。首页仅预览个人列表的前五项。
- 用户只能管理个人重点工作列表，不能通过该面板创建或删除业务任务、修改任务内容或改变任务状态。
- 修改个人十大重点工作只影响当前用户首页的个人选择和顺序，不修改原任务或“公司十大重要任务”的系统排序。
- 个人十大中的任务在该用户的月视图任务条上显示“个人重点”星标；移出个人十大后同步取消星标。该标记不代表任务的共享优先级，也不改变其他用户的展示。
- 用户可选择的范围是本人当前“我的任务”中的未完成任务；不要求所选任务同时出现在系统生成的“公司十大重要任务”中。已完成任务不能加入个人十大；已取消并归档的任务不属于当前候选范围。

### 5.3 任务来源

个人十大重点工作的可选内容为当前用户“我的任务”中的未完成本人任务，按需求 01 的角色和权限规则确定。团队长或部门经理派发给下属、但本人不负责执行的任务，不会出现在本人个人十大重点工作中。

### 5.4 首页展示与交互

- 首页卡片最多预览个人重点列表的前五项；进入二级界面后最多展示完整的十项，不足时按实际数量展示。
- 每项显示任务标题、当前状态和截止时间；在个人重点二级界面点击某项进入原任务详情。
- 用户可以从本人未完成任务中选择或移除个人重点；排序采用长按拖拽列表项的方式完成，系统保存当前用户的选择和顺序。非编辑状态下点击任务进入详情，避免排序手势与导航误触。
- 用户不能借由排序操作更改任务的创建者、责任人、状态或任务层级。

个人十大重点工作中不包含单独创建的学习计划、个人习惯或非任务提醒；这些内容不属于本需求定义的任务面板。

### 5.5 顺序保存

个人重点任务的选择和排序按当前用户单独保存，不影响其他用户，也不改变“公司十大重要任务”的系统顺序。首次预填后，个人重点列表不随公司十大榜单变化自动增删；新进入“我的任务”的任务由用户自行选择。如果任务不再属于本人“我的任务”、完成状态变为“已完成”或任务被取消归档，系统应将其从个人重点工作中移除。

## 6. 最近日志

### 6.1 面板定位

首页日志面板回答：

> 我最近记录了哪些工作？

首页卡片按日志日期从新到旧展示当前用户最近 5 篇已提交日志摘要，不要求每天都有日志，也不为没有日志的日期补空白记录。草稿不显示在首页。首页只负责展示摘要和快捷跳转，不承载完整日志填写和管理功能。

### 6.2 与独立日志 Tab 的关系

```text
同一组 DailyLog 记录
      │
      ├─ 首页：展示最近五篇摘要和今日日志快捷入口
      │
      └─ 日志 Tab：新增、查看和编辑完整内容，查询全部历史
```

首页和日志 Tab 必须读取同一组日志数据，不得为首页摘要复制或另存日志内容。

### 6.3 首页列表与空状态

首页最近日志卡片最多显示五篇已提交日志；不足五篇时按实际数量显示。每条摘要至少显示日志日期和日志摘要。摘要沿用日志列表中的摘要内容，不在首页单独维护。由于草稿不显示在首页，保存草稿不会使其进入最近日志列表。

```text
最近日志（最多5篇）                  [填写今日日志]

9月23日 · 已提交
完成任务接口设计和数据库字段调整……

9月22日 · 已提交
整理了本周需求问题，并与团队讨论……
...

[填写今日日志]
```

即使今天尚未填写，只要存在历史日志，首页仍展示最近日志列表，并提供“填写今日日志”入口。

没有任何日志时，显示空状态和填写入口：

```text
最近日志

暂无日志记录
[填写今日日志]
```

### 6.4 点击和跳转规则

```text
首页“填写今日日志”
→ 日志 Tab / 今日日志编辑页

点击一篇日志摘要
→ 日志 Tab / 对应日期 / 详情状态

直接点击底部“日志”
→ 日志 Tab / 日历与选中日期详情
```

用户在日志 Tab 提交日志后，首页最近日志列表应同步更新并按日期重新排序；修改已提交日志时，对应摘要同步更新。保存草稿不影响首页最近日志列表。

### 6.5 独立日志 Tab 的职责

独立日志 Tab 负责：

- 填写和编辑当天日志
- 填写今日完成和明日计划
- 查看历史日志
- 按月历和日期查看日志详情
- 管理者查看权限范围内的下属日志

日志表单不设置任务关联、问题与风险字段；日志详情仅记录当日工作和可选的明日计划。管理者可从查看对象选择窗口按人员信息查找授权范围内的下属。

### 6.6 管理角色规则

首页最近日志列表始终展示当前登录用户自己的日志，不展示下属日志。

管理角色需要查看下属日志时，应进入独立日志 Tab：

| 用户角色 | 日志 Tab 可查看范围 |
| --- | --- |
| 普通员工 | 自己的日志 |
| 团队长 | 自己的日志和本团队组织范围内直接及间接下属的已提交日志 |
| 部门经理 | 自己的日志及本部门组织范围内直接及间接下属的已提交日志 |
| 创始人 | 可筛选查看全公司成员的已提交日志，默认查看本人 |

管理者默认查看本人日志；需要查看下属时沿授权组织层级筛选。团队长范围限本团队，部门经理范围限本部门，创始人范围为全公司。

日志在 MVP 中为只读查看内容：管理者不能评论、退回或要求补充下属日志，日志不进入验收流程。

### 6.7 首页不承载的功能

首页最近日志面板不提供：

- 完整日志表单
- 历史日期切换
- 下属日志查看
- 日志搜索和筛选
- 日志统计
- 附件管理

## 7. 四大面板汇总

| 面板 | 内容决定者 | 系统维护者 | 数据性质 | 首页主要操作 |
| --- | --- | --- | --- | --- |
| 公司十大重要事项 | 公司管理层 | 管理员 | 公司事件与信息 | 查看详情 |
| 公司十大重要任务 | 当前用户的任务列表 | 系统 | 任务二级界面最多十项；首页预览前五 | 查看全部、查看任务详情 |
| 个人十大重点工作 | 当前用户 | 系统保存个人选择与排序 | 从本人未完成任务中自主选出的重点任务；列表最多十项，首页预览前五 | 查看全部、选择任务、拖拽排序 |
| 最近日志 | 当前用户 | 当前用户 | 本人最近已提交日志摘要，首页最多五篇 | 查看日志、填写今日日志 |

四个面板可以概括为：

> 公司重要事项是“公司发生了什么”，公司十大重要任务是“系统按来源优先级从我的任务中列出哪些任务”，个人十大重点工作是“我自己从未完成的本人任务中挑选哪些并如何排序”，最近日志是“我近期记录了什么工作”。首页卡片预览五条，相关二级列表最多显示十条。

## 8. 初步验收场景

### 场景 1：管理员发布公司重要事项

- **假如** 管理员已经在 Web 端填写完整的重要事项内容
- **当** 管理员发布该事项并将其加入首页展示
- **那么** 所有移动端用户可以在“公司十大重要事项”中看到相同摘要并进入详情

### 场景 2：首页重要事项预览与二级列表

- **假如** 当前存在 6 至 10 条已发布的重要事项
- **当** 用户查看首页卡片并进入“查看全部”二级界面
- **那么** 首页按管理员顺序预览前五条，二级界面按同一顺序展示全部已发布事项及其完整信息

### 场景 3：系统按当前用户生成公司十大重要任务

- **假如** 当前用户的“我的任务”列表包含多项任务
- **当** 用户打开首页
- **那么** 系统先合并本人未完成任务，再按来源优先级、来源内截止时间及创建时间依次排序后取前十；首页仅预览前五，二级界面可查看最多十项，不展示分配给下属且本人不负责执行的子任务

### 场景 4：不同用户查看公司十大重要任务

- **假如** 两名用户分别拥有不同的本人任务列表
- **当** 两名用户分别打开首页
- **那么** 系统根据各自的任务列表生成各自的“公司十大重要任务”，而非显示一份全公司统一任务榜单

### 场景 5：个人十大独立选择和排序

- **假如** 当前用户的“我的任务”中有一项未完成任务未进入系统生成的“公司十大重要任务”前十
- **当** 用户将该任务选入“个人十大重点工作”，在二级界面长按拖拽调整顺序，再点击该任务
- **那么** 该任务可以出现在个人重点列表中；首页预览前五，二级界面最多展示十项；点击后进入原任务详情，且不改变公司十大系统顺序或任务本身

### 场景 6：任务变化后同步首页

- **假如** 用户的任务被新增、完成、取消或从当前任务列表移除
- **当** 系统重新展示首页任务面板
- **那么** 公司十大按来源优先级、来源内截止时间及创建时间重新取前十；个人十大保留用户对仍未完成任务的选择，任务完成、取消归档或不再属于本人任务列表时自动移除

### 场景 7：当前任务不足十项

- **假如** 当前用户符合展示条件的未完成任务少于十项
- **当** 用户打开首页
- **那么** 公司十大最多展示符合条件的前十项，个人十大最多展示用户选定的未完成任务；两者均不使用个人习惯或非任务内容补足

### 场景 8：查看最近已提交日志摘要

- **假如** 当前用户已有多篇不同日期的日志
- **当** 用户打开首页
- **那么** 首页“最近日志”卡片按日期从新到旧展示最多五篇已提交日志摘要，点击填写日志快捷入口进入日志 Tab，点击摘要进入对应日期的日志详情

### 场景 9：最近日志不足五篇或为空

- **假如** 当前用户的已提交日志少于五篇或尚无已提交日志
- **当** 用户打开首页
- **那么** 系统展示已有日志；没有日志时显示空状态，并提供“填写今日日志”入口

### 场景 10：填写今日日志后更新最近列表

- **假如** 用户通过独立日志 Tab 提交今日日志
- **当** 用户返回首页
- **那么** 首页将该日志纳入最近列表、同步摘要和状态，并按日期重新排序

### 场景 11：管理者查看首页日志

- **假如** 当前用户是团队长、部门经理或创始人
- **当** 该用户打开首页
- **那么** 首页“最近日志”只显示该用户本人的日志，最多五篇，不显示下属日志

### 场景 12：普通用户尝试维护公司重要事项

- **假如** 当前用户不是管理员
- **当** 该用户尝试新增、修改、排序或下架公司重要事项
- **那么** 系统拒绝操作，且不产生公司重要事项数据变更

### 场景 13：公司重要事项必填字段校验

- **假如** 管理员新增或编辑公司重要事项
- **当** 事项标题、内容摘要或完整正文任一必填字段为空并尝试发布
- **那么** 系统阻止发布并提示补全；附件为空不阻止发布，发布时间和发布人由系统记录

### 场景 14：首页任务摘要不显示进度百分比

- **假如** 当前用户的任务有进度百分比
- **当** 该任务出现在“公司十大重要任务”或“个人十大重点工作”面板
- **那么** 首页仅显示任务标题、状态和截止时间，不显示进度百分比

### 场景 15：管理者尝试处理下属日志

- **假如** 管理者正在查看权限范围内下属的已提交日志
- **当** 该管理者尝试评论、退回或要求补充日志
- **那么** MVP 不提供这些操作，日志保持只读且不进入验收流程
