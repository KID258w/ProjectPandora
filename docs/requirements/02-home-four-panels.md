# 需求 02：首页信息面板与个人事项日历

## 文档信息

- 当前版本：`v0.9`
- 当前状态：已确认首页任务通知铃铛及未读红点规则；组织关系入口面向所有 App 用户开放
- 所属阶段：Sprint 0——需求分析与产品设计
- 当前范围：移动端首页公司信息面板、任务信息面板、嵌入式个人事项月历与任务通知铃铛
- 关联需求：`01-task-creation-and-acceptance.md`、`09-personal-daily-items.md`

## 1. 需求目标

移动端首页通过两个概览面板和个人事项月历，为用户提供公司信息、本人任务及个人安排：

```text
公司发生了什么
      ↓
我当前有哪些重要任务
      ↓
我为自己安排了哪些每日事项
```

首页上方保留两个并列概览面板，下方直接显示每日事项月历：

```text
┌──────────────────┬──────────────────┐
│ 事件纪             │ 任务看版           │
└──────────────────┴──────────────────┘
每日事项
┌────────────────────────────────────┐
│ 月份切换、新建事项、个人事项月历     │
└────────────────────────────────────┘
```

“事件纪”和“任务看版”是统一尺寸的并列概览卡片；“任务看版”最多预览 5 条，二级界面最多展示 10 条。首页下方直接嵌入完整的个人事项月历，用户无需再从事项预览卡片跳转到单独月历页。“每日寄语”卡片及个人化问候、职位和日期文字已从首页移除。“任务看版”由系统从当前用户未完成任务中按来源顺序选出。每日事项是用户自行创建的个人备忘录，与公司任务及 Web 管理审计分离，具体规则见需求 09。

“事件纪”读取现有公司事项数据，“任务看版”读取当前用户任务，“每日事项”月历读取当前账号的个人备忘录，不改变公司任务资源或接口命名。

## 2. 通用设计原则

首页模块遵守以下共同规则：

- 首页上方采用两个等宽并列卡片；卡片高度相同，依据预览条数自适应，并为最多五条完整预览留出空间。屏幕高度不足时，首页整体纵向滚动。
- 首页顶部不显示“你好”问候语、员工职位/组织信息或当前日期。
- 首页下方直接承载每日事项月历的日期选择、创建、详情、编辑、删除和拖动操作；月历本身可在其可视区域内纵向滚动。
- “事件纪”首页卡片只显示事项标题；“查看全部”进入“事件纪”二级列表，列表项可折叠/展开正文，不跳转独立详情页。任务和日志仍按各自需求进入对应界面。
- 首页数据来自公司重要事项、当前用户任务和当前账号每日事项，不单独复制业务数据。
- “事件纪”面向所有移动端用户展示；任务和每日事项按当前登录用户展示各自的数据。
- 个人级内容只展示当前登录用户本人的信息。每日事项只属于创建它的员工；其他员工和 Web 管理端不能查看或管理。
- 团队长、部门经理和创始人在首页看到的任务仍然是本人相关内容，不自动替换为下属内容。日志通过底部“日志”入口进入。
- 所有 App 用户都可通过“组织关系”浏览全公司组织树和成员资料。只有具备相应既有权限的用户，才会在成员资料页看到只读的任务、日志或工作视图入口；下属工作统一从组织关系进入，权限规则与需求 01、03、04、08 一致。
- 首页顶部提供任务通知铃铛；直属下级待当前用户审批的任务、以及他人派发且已审批进入本人任务列表的新任务，均可产生未读通知。通知明细和审批、执行操作仍在对应任务页面处理。
- 任务通知入口以铃铛图标按钮显示，不显示“任务通知”文字按钮；无障碍描述为“任务通知”。未读红点仍显示在铃铛上。

### 2.1 任务通知铃铛

- 有未读任务通知时，铃铛显示红点；无未读通知时不显示。
- 点击铃铛进入通知列表时不改变任何通知的已读状态，红点继续显示；用户点击具体通知后才将该条标记为已读，其它未读通知继续保持未读。
- 通知分为“待你审批”和“新任务已分配”两类。审批通知只针对当前用户的直属下级创建且等待本人审批的任务；新任务通知针对其他人创建、审批通过并已进入本人“我的任务”的任务。
- 点击通知进入对应任务详情；审批通知仅允许有权审批的直属上级执行审批，通知页本身不改变任务状态。

## 3. 事件纪

### 3.1 面板定位

“事件纪”回答：

> 公司最近发生了什么重要事情？

内容主要包括公司信息、重大事件、重要成果和里程碑，例如：

- 公司完成融资
- 与重要客户达成合作
- 新产品正式上线
- 重大项目通过验收
- 公司组织架构调整
- 公司获得重要奖项

### 3.2 内容产生与维护

```text
公司管理层确定公开内容
        ↓
管理员在 Web 端录入和维护
        ↓
发布到移动端首页
        ↓
所有移动端用户查看
```

管理员可以：

- 新增重要事项
- 编辑事项内容
- 手动设置首页展示顺序
- 发布或下架事项

公司重要事项不设“置顶”机制；首页展示顺序由管理员手动排序决定。

普通移动端用户只能查看，不能新增、修改或删除公司重要事项。

当前版本不要求公司重要事项图片或附件管理。已存在的后端附件能力暂时保留为技术实现，不作为本次移动端功能验收项。

### 3.3 建议字段

公司重要事项至少包含：

- 必填：事项标题、内容摘要、完整正文
- 系统记录：发布时间、发布人
- 管理员维护：首页展示顺序、发布状态

### 3.4 首页与二级列表展示

首页卡片最多显示管理员排序靠前的 5 个事项标题，不显示发布时间或摘要。

点击“事件纪”卡片中的“查看全部”进入事件纪二级界面，最多展示 10 条已发布事项。二级界面以列表展示事项；列表项可折叠，展开后在当前列表中显示完整正文。这里不进入独立事项详情页，也不展示或下载附件。事项数量少于 10 条时按实际数量展示。

后续版本可以另行增加独立详情页和事项附件上传、下载能力；如果附件用于任务材料或任务交付，应在任务模块的需求中单独设计，不自动纳入公司重要事项。

公司重要事项不是任务，因此不包含：

- 任务负责人
- 任务进度
- 父子任务
- 提交与验收
- 任务派发

## 4. 任务看版

### 4.1 面板定位

“任务看版”不是对所有用户相同的公司级任务榜单，而是**系统按任务来源优先级从当前登录用户的任务中选出的前十项**。它回答：

> 我的任务中，哪些由他人派发、哪些由本人创建并承担的任务会被系统列入前十？

不同用户看到的内容可以不同。普通员工看到分配给自己的任务；创始人、部门经理和团队长还可以看到自己创建并由自己负责的任务。管理者派发给下属的子任务，不会仅因派发者身份进入其本人任务面板；按需求 01 保留在本人“我的任务”中的根任务仍属于本人任务。

### 4.2 数据来源与生成规则

```text
当前用户的“我的任务”
        ↓
合并本人任务，并先按来源、再按状态排序
        ↓
自动截取前十项（不足十项则按实际数量展示）
        ↓
最多十项候选组成“任务看版”列表；首页卡片只预览其中前 5 项
```

- 面板直接读取需求 01 中当前用户的任务，不创建第二份任务数据。
- 默认来源顺序为：他人创建并分配给本人的任务优先，其次本人创建并由本人承担的任务；不区分或标记跨部门任务。该来源顺序是第一排序条件。
- 任务状态只有“未完成”和“已完成”两种；候选任务均为未完成，因此同一来源内按截止时间从早到晚排列，截止时间相同时按任务创建时间从早到晚排列。
- 已完成任务不进入候选列表。
- 取消归档任务不进入候选列表；级联取消归档的未完成后代任务同样排除。
- 系统自动选取前十项；用户不能在此面板中新增、删除、置顶或调整顺序。
- 任务列表变化后，面板内容随之更新。
- 用户点击某项后进入原任务详情，并按需求 01 中的权限操作。
- 面板展示任务标题、当前状态和截止时间，不显示进度百分比；不在首页另行编辑任务内容或状态。

### 4.3 各角色的任务来源

| 当前用户角色 | 可进入该用户任务列表的本人任务 |
| --- | --- |
| 普通员工 | 上级分配给本人的任务 |
| 团队长 | 上级分配给本人的任务、团队独立任务中由本人负责的任务、分配给本人的子任务 |
| 部门经理 | 他人分配给本人的任务（包括其他部门经理通过统一入口派发的任务）、本人创建并负责的任务 |
| 创始人 | 本人创建并负责的公司级任务、分配给本人的子任务 |

管理者创建任务并分配给下属时，只有本人同时承担了明确的执行子任务，该子任务才进入本人的任务列表；单纯作为派发者或管理者不等于本人负责执行。

### 4.4 展示与维护边界

- 系统列表先按“他人派发 → 本人创建并承担”的来源顺序，再按截止时间、创建时间排序，生成最多十项。跨部门协作任务按普通的“他人派发”任务处理，不建立单独类别。候选项均为“未完成”，已完成及已取消归档任务排除。首页卡片仅预览该列表前 5 项，用户不能修改此面板的内容和顺序。
- 点击首页卡片“查看全部”进入任务看版二级界面，可查看最多十项任务；点击其中一项进入对应任务详情。任务本身的修改权限仍由需求 01 控制。
- 本面板显示的是个人任务，不展示全公司任务总榜、其他部门的任务或下属任务明细。
- “十大”表示最多十项，不足十项时不补充个人习惯或其他非任务内容。

## 5. 每日事项

首页下半部直接显示当前账号的完整个人事项月历，不再显示每日事项预览卡片，也不要求用户跳转到另一个页面。用户可以在首页切换月份、选择年月、新建事项、查看日期事项列表、查看事项详情、编辑、删除及拖动事项。月历字段、颜色、节假日、溢出列表和交互规则见[需求 09：个人每日事项](09-personal-daily-items.md)。

## 6. 独立日志 Tab 的职责

独立日志 Tab 负责：

- 填写和编辑当天日志
- 填写今日完成和明日计划
- 查看历史日志
- 按月历和日期查看日志详情
- 管理者查看权限范围内的下属日志

日志表单不设置任务关联、问题与风险字段；日志详情仅记录当日工作和可选的明日计划。所有 App 用户可从“组织关系”搜索或展开公司成员；只有对目标成员具备既有日志查看权限的用户，才可从成员资料页进入其已提交日志。

### 6.1 管理角色规则

具备下属日志查看权限的管理角色应从“组织关系”打开目标成员资料，再点击“查看日志”；组织资料可被全体 App 用户浏览，但不会扩大日志权限。普通日志 Tab 默认打开当前用户自己的日志：

| 用户角色 | 日志 Tab 可查看范围 |
| --- | --- |
| 普通员工 | 自己的日志 |
| 团队长 | 自己的日志和本团队组织范围内直接及间接下属的已提交日志 |
| 部门经理 | 自己的日志及本部门组织范围内直接及间接下属的已提交日志 |
| 创始人 | 可筛选查看全公司成员的已提交日志，默认查看本人 |

管理者默认查看本人日志；需要查看下属时先在组织关系页按授权组织层级选择成员。团队长范围限本团队，部门经理范围限本部门，创始人范围为全公司。日志页不再单独提供下属选择器。

日志在 MVP 中为只读查看内容：管理者不能评论、退回或要求补充下属日志，日志不进入验收流程。

## 7. 首页模块汇总

| 面板 | 内容决定者 | 系统维护者 | 数据性质 | 首页主要操作 |
| --- | --- | --- | --- | --- |
| 事件纪 | 公司管理层 | 管理员 | 公司事件与信息 | 查看全部、在列表中展开正文 |
| 任务看版 | 当前用户的任务列表 | 系统 | 任务二级界面最多十项；首页预览前五 | 查看全部、查看任务详情 |
| 每日事项月历 | 当前用户 | 当前用户 | 当前月份可见网格中的全部本人备忘录及节假日标记 | 在首页月历中切换月份、创建、查看、编辑、拖动、删除 |

首页模块可以概括为：

> 事件纪是“公司发生了什么”，任务看版是“系统按来源优先级从我的任务中列出哪些任务”，首页下半部的每日事项月历用于直接安排和查看个人备忘录。

## 8. 初步验收场景

### 场景 1：管理员发布公司重要事项

- **假如** 管理员已经在 Web 端填写完整的重要事项内容
- **当** 管理员发布该事项并将其加入首页展示
- **那么** 所有移动端用户可以在“事件纪”中看到相同的前五个事项标题，并在二级列表中折叠/展开事项正文

### 场景 2：首页重要事项预览与二级列表

- **假如** 当前存在 6 至 10 条已发布的重要事项
- **当** 用户查看首页卡片并进入“查看全部”二级界面
- **那么** 首页按管理员顺序预览前五条，二级界面按同一顺序展示全部已发布事项及其完整信息

### 场景 3：系统按当前用户生成任务看版

- **假如** 当前用户的“我的任务”列表包含多项任务
- **当** 用户打开首页
- **那么** 系统先合并本人未完成任务，再按来源优先级、来源内截止时间及创建时间依次排序后取前十；首页仅预览前五，二级界面可查看最多十项，不展示分配给下属且本人不负责执行的子任务

### 场景 4：不同用户查看任务看版

- **假如** 两名用户分别拥有不同的本人任务列表
- **当** 两名用户分别打开首页
- **那么** 系统根据各自的任务列表生成各自的“任务看版”，而非显示一份全公司统一任务榜单

### 场景 5：首页显示完整每日事项月历且与公司任务分离

- **假如** 当前用户创建了自己的每日事项
- **当** 用户打开首页
- **那么** 首页下半部直接显示本人当前月份的事项月历；事项不进入公司任务列表、任务看版或操作审计

### 场景 6：首页月历支持事项操作

- **假如** 用户在首页查看个人事项月历
- **当** 用户选择日期或点击事项任务条
- **那么** 用户可以直接打开日期列表或事项详情，并在首页月历中创建、编辑、拖动和删除事项

### 场景 7：个人每日事项空状态

- **假如** 当前用户没有任何每日事项
- **当** 用户查看首页
- **那么** 月历显示清晰的空状态并提供新建事项入口，空状态不影响公司任务或事件纪

### 场景 8：首页不显示个人问候信息

- **假如** 用户打开首页
- **当** 首页加载完成
- **那么** 顶部不显示“你好”问候语、员工职位/组织信息或日期，也不显示每日寄语卡片

### 场景 10：普通用户尝试维护公司重要事项

- **假如** 当前用户不是管理员
- **当** 该用户尝试新增、修改、排序或下架公司重要事项
- **那么** 系统拒绝操作，且不产生公司重要事项数据变更

### 场景 11：公司重要事项必填字段校验

- **假如** 管理员新增或编辑公司重要事项
- **当** 事项标题、内容摘要或完整正文任一必填字段为空并尝试发布
- **那么** 系统阻止发布并提示补全，发布时间和发布人由系统记录

### 场景 12：首页任务摘要不显示进度百分比

- **假如** 当前用户的任务有进度百分比
- **当** 该任务出现在“任务看版”面板
- **那么** 首页仅显示任务标题、状态和截止时间，不显示进度百分比

### 场景 13：管理者尝试处理下属日志

- **假如** 管理者正在查看权限范围内下属的已提交日志
- **当** 该管理者尝试评论、退回或要求补充日志
- **那么** MVP 不提供这些操作，日志保持只读且不进入验收流程

### 场景 14：首页存在待审批任务通知

- **假如** 当前用户的直属下级创建了等待该用户审批的任务
- **当** 当前用户打开首页
- **那么** 首页铃铛显示红点；更高层级的只读查看者不因此收到待审批通知

### 场景 15：首页存在已派发的新任务通知

- **假如** 其他用户创建的任务已审批通过并进入当前用户“我的任务”
- **当** 当前用户尚未查看该通知并打开首页
- **那么** 首页铃铛显示红点；任务仍按正常任务流程处理

### 场景 16：查看任务通知

- **假如** 当前用户有未读的审批或新任务通知
- **当** 用户点击铃铛并打开通知列表
