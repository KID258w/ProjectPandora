# 需求 04：月、周、日工作视图

## 文档信息

- 当前版本：`v0.4`
- 当前状态：视图范围及当前/历史周期展示规则已按团队讨论收敛，尚未提交甲方确认
- 所属阶段：Sprint 0——需求分析与产品设计
- 当前范围：移动端个人工作视图及管理者只读查看下属工作视图
- 关联需求：`01-task-creation-and-acceptance.md`、`03-daily-log-module.md`

## 1. 需求目标

月、周、日工作视图只聚合展示用户本人或筛选对象的正式任务及任务进度、状态变化，不展示日志相关信息。

```text
任务安排
任务进度记录
任务状态历史
    ↓
任务工作视图
    ↓
月视图 → 周视图 → 日视图
看分布    看每天    看详情
```

三个视图不要求用户额外填写或重复维护数据：

- 月视图：展示整月任务安排、跨度和关键节点。
- 周视图：按日期展示每天实际产生的任务进度和状态变化。
- 日视图：展示某一天的任务安排、任务状态和进度变化。

“视图”Tab 不显示日志正文、摘要、草稿状态、日志标记或日志入口；日志填写、历史查询和上级查看日志均在独立“日志”Tab 中进行。

## 2. 页面入口与通用结构

移动端底部导航提供独立的“视图”Tab。进入后通过页面按钮切换月、周、日视图：

```text
工作视图

[月] [周] [日]

＜ 当前日期范围 ＞    [回到今天]
```

进入视图 Tab 默认打开当前周的周视图。用户可以：

- 点击“月、周、日”按钮切换视图。
- 切换上一个或下一个月、周、日。
- 点击“回到今天”返回当前日期所在视图。
- 在月视图或周视图点击日期进入对应日视图。

所有角色进入视图 Tab 时默认查看本人工作视图。管理者需要了解下属工作时，通过“查看对象”筛选切换到权限范围内的团队或成员；切换后页面应明确显示当前查看对象，并提供清除筛选、返回本人视图的入口。月/周/日切换和日期导航在切换查看对象时保持一致。

工作视图只负责只读展示任务数据，不提供任务详情跳转、任务编辑、进度更新、验收或退回操作；日志功能不属于本 Tab。

## 3. 数据来源

| 展示内容 | 数据来源 |
| --- | --- |
| 任务持续范围 | 任务开始时间、截止时间 |
| 任务优先级和负责人 | 正式任务记录 |
| 截至某日的任务状态 | 任务状态历史 |
| 每日任务进度变化 | 任务进度历史 |
| 提交、验收、退回和完成事件 | 任务状态变更记录 |

系统不得为工作视图复制或单独维护任务、进度数据。视图只查询并组织已有任务记录，不读取 DailyLog 或日志与任务的关联关系。

## 4. 工作视图的任务范围

用户查看本人的工作视图时，只展示当前用户本人负责或执行的正式任务；管理者筛选到某位下属时，则复用同一视图展示该下属本人负责或执行的任务：

- 普通员工：分配给自己的任务。
- 团队长：上级分配根任务、团队独立根任务和本人子任务。
- 部门经理：创始人派发给自己的根任务、本人创建并负责的部门根任务和本人子任务。

团队长和部门经理向下属派发、但本人不负责执行的任务，不自动混入管理者本人的工作视图。查看下属工作时，管理者通过查看对象筛选切换到对应成员，而不是把整个团队或部门的任务混入个人视图。任务分配和验收仍在任务模块处理。

MVP 暂不在工作视图中展示：

- 公司十大重要事项
- 公司十大重要任务
- 用户自建学习计划和重复习惯
- 整个团队或部门的多人叠加日历

## 5. 月视图

### 5.1 视图定位

月视图回答：

> 这个月什么时候在做什么？有哪些重要截止时间？

月视图重点展示计划和分布，不展开每天的完整工作内容。

### 5.2 展示内容

月视图展示：

- 当前用户任务的开始和截止范围
- 长期任务的持续时间
- 任务开始日期和截止日期
- 高优先级和已逾期任务

### 5.3 长期任务展示

长期任务使用跨日期任务条表示：

```text
9月18日 ───────────── 9月23日
          数据库设计
```

不得将同一项长期任务在每一天重复显示为独立任务：

```text
错误示例：
18日 数据库设计
19日 数据库设计
20日 数据库设计
21日 数据库设计
```

### 5.4 月历布局示意

```text
┌──────────────────────────────────┐
│ 工作视图                         │
│        [月●] [周] [日]            │
│  ＜          2026年9月        ＞  │
├──────────────────────────────────┤
│ 周一    周二    周三    周四    周五 │
│                                  │
│ 18      19      20      21      22 │
│ 数据库设计 ━━━━━━━━━━━━━━━━━━━━━━━ │
│                                  │
│ 25      26      27      28      29 │
│ 登录接口 ━━━━━━━━━ 截止            │
└──────────────────────────────────┘
```

### 5.5 月视图规则

- 单个日期区域只展示有限数量的任务条，超出时显示“还有 N 项”。
- 任务跨月时，在月初或月末显示延续标记。
- 截止日期使用清晰的节点标识。
- 已逾期任务显示逾期状态。
- 点击日期进入对应日视图。
- 只有截止时间、没有开始时间的任务，只在截止日显示。

## 6. 周视图

### 6.1 视图定位

周视图回答：

> 这一周每天有哪些任务进度或状态变化？

周视图以日期为主轴，不做整周进度复盘；当前周的未完成任务区只作待办清单，不重复展开进度记录。

查看当前周时，在周内逐日进展之外增加可折叠的“本周未完成任务”区域，集中展示当前仍未完成、且已开始、已逾期或计划在本周开始的本人执行任务。已完成、已取消以及计划在未来周开始的任务不列入该区域。查看过去周或未来周时不显示这个区域。

### 6.2 周视图布局示意

```text
┌──────────────────────────────────┐
│ 工作视图                         │
│        [月] [周●] [日]            │
│  ＜      9月21日—9月27日      ＞  │
│              [回到本周]           │
├──────────────────────────────────┤
│ 本周未完成任务（2）       [收起]  │
│ 数据库设计  进行中    截止9月25日  │
│ 登录接口    待验收    截止9月26日  │
├──────────────────────────────────┤
│ 周一 · 9月21日                   │
│                                  │
│ 任务进度                         │
│ 数据库设计   20% → 40%           │
│ 完成表结构设计                    │
│                                  │
│ 登录接口开发 30% → 60%           │
│ 完成接口主体                      │
│                                  │
│                         [查看当天]│
├──────────────────────────────────┤
│ 周二 · 9月22日                   │
│                                  │
│ 任务进度                         │
│ 数据库设计   40% → 65%           │
│ 完成ER图设计                      │
│                                  │
│                         [查看当天]│
├──────────────────────────────────┤
│ 周三 · 9月23日                今天 │
│                                  │
│ 登录接口开发 60% → 100%          │
│ 已提交团队长验收                  │
│                                  │
│                         [查看当天]│
├──────────────────────────────────┤
│ 周四 · 9月24日                   │
│                                  │
│                         [查看当天]│
└──────────────────────────────────┘
```

### 6.3 周视图数据规则

- 每一天只展示当天实际产生的任务进度记录和任务状态变化。
- 没有更新进度的进行中任务，不在周视图每天重复显示。
- “本周未完成任务”区域只展示任务名称、当前任务状态和截止日期，不重复展开每日进度记录。
- 任务提交、验收通过、退回修改和标记完成等状态变化可以作为当天动态展示。
- 团队长和部门经理的本人子任务没有进度百分比时，显示“未完成”或“已完成”等状态变化。
- 当前周内某天没有任务进度或状态变化时，只保留日期标题，不显示空的进度信息；查看过去周时也只展示实际发生过的任务变化。
- 历史周中的每日任务状态均以各自然日结束时为冻结点；之后的任务变化不改写已结束日期的状态。
- 未来周不显示未完成任务区域；未来日期按计划任务规则展示任务安排，不生成进度记录。
- 点击“查看当天”进入对应日视图。

### 6.4 周视图不展示的内容

周视图不额外展示：

- 按任务组织的整周进度列表
- 没有变化的任务每日快照

这些内容会造成任务信息和每日信息重复。

## 7. 日视图

### 7.1 视图定位

日视图回答：

> 选中的这一天有哪些任务？任务发生了什么变化？

日视图只展示当天相关任务及任务动态。

### 7.2 日视图布局示意

```text
┌──────────────────────────────────┐
│ 工作视图                         │
│        [月] [周] [日●]            │
│  ＜     2026年9月23日 周三    ＞  │
│              [回到今天]           │
├──────────────────────────────────┤
│ 今日未完成任务（2）               │
│ 数据库设计  进行中    截止9月25日  │
│ 登录接口    待验收    截止9月26日  │
├──────────────────────────────────┤
│ 当日任务与进展                   │
│                                  │
│ 数据库设计                       │
│ 高优先级 · 进行中 · 截止9月25日   │
│ 截至当天进度：65%                │
│                                  │
│ 今日更新 10:30                   │
│ 40% → 65%                       │
│ 完成ER图设计，确认表关系          │
│                                  │
│                                  │
│ 登录接口开发                     │
│ 待验收 · 进度100%                │
│ 今日动态 16:20                   │
│ 完成异常处理并提交团队长验收      │
│                                  │
└──────────────────────────────────┘
```

### 7.3 当日任务纳入规则

日视图按日期类型区分展示内容：

- **今天：** 顶部显示本人当前未完成任务（已开始、已逾期或计划今天开始；排除已完成、已取消及未来才开始的任务），下方只显示当天实际发生的任务进度或状态变化。
- **过去日期：** 不显示未完成任务区，只显示该日实际发生过进度或状态变化的任务；当天没有变化的任务不显示。
- **未来日期：** 不显示未完成任务区，只按任务开始时间和截止时间展示计划任务，不生成进度或状态变化。

“今日未完成任务”只列任务名称、当前状态和截止日期；下方的任务进展区域只列当天发生的进度或状态变化。两处承担不同作用，不在未完成任务区重复展开进展说明。

### 7.4 查看今天

查看今天时：

- 显示“今日未完成任务”清单，包括没有当天进度更新的未完成任务。
- 下方只展示当天实际发生的任务进度或状态变化；没有进展的任务不显示进度信息。
- 工作视图不显示日志状态、摘要、正文或填写入口。
- 工作视图只读，不提供任务详情跳转或任务操作。

### 7.5 查看过去日期

查看历史日期时只展示该日实际发生过进度或状态变化的任务，并以该自然日结束时的任务状态和进度作为冻结结果，而不是显示任务现在的最终状态。自然日结束即为冻结时机；后续日期的变化不得改写已结束日期的历史结果。

例如任务当前已经完成，但查看 9 月 20 日时应显示：

```text
截至9月20日：进行中，进度40%
```

不得直接显示当前的“已完成、100%”。这要求系统保留任务进度历史和任务状态变更历史。

### 7.6 查看未来日期

查看未来日期时：

- 只显示根据开始时间和截止时间推导出的计划任务。
- 不提前生成任务进度记录。
- 页面按计划任务规则展示任务，不显示未完成任务区或进度变化记录。

工作视图不展示当日日志或任何日志相关状态；需填写或查看日志时，用户应切换至独立“日志”Tab。

## 8. 管理者筛选查看下属工作视图

所有角色默认打开本人的工作视图。管理者可以通过“查看对象”筛选切换到权限范围内的团队或成员：

```text
团队长：本人或本团队组织树成员
部门经理：本人或本部门组织树成员
创始人：本人或公司范围内成员
```

筛选规则：

- 默认查看对象为“本人”，不自动展示下属数据。
- 管理者筛选范围与需求 03 一致：团队长可筛选本团队组织树，部门经理可筛选本部门组织树，创始人可筛选全公司成员。
- 不得通过筛选查看权限范围之外的部门或成员。
- 筛选到单个成员后，月、周、日视图只展示该成员本人负责或执行的任务及任务进度、状态历史；当前周和今天的未完成任务清单也按该成员本人任务生成。
- 页面持续显示当前查看对象及其组织归属，并提供清除筛选、返回本人视图的入口。
- 管理者查看下属任务数据时只有只读权限，不能修改任务、更新进度，也不能在工作视图中验收或退回任务。
- 工作视图不读取、不显示下属日志；日志查看权限由需求 03 的独立日志 Tab 处理。
- 任务分配和验收仍在任务模块处理；部门经理不通过任务界面逐层查看员工任务，详见需求 01。

MVP 不将整个团队或部门的所有人员任务叠加在同一个月历中。管理者按照单个人员筛选并复用相同的月、周、日视图。

## 9. 特殊情况处理

- 已逾期任务继续显示，并增加逾期标记。
- 已取消任务不再出现在取消日期之后的未来视图中，但保留取消前的历史记录。
- 任务跨月时，月视图显示延续标记。
- 一天任务过多时，月视图收起超出部分，日视图展示完整列表。
- 一天存在多次同一任务进度更新时，周视图可以按时间顺序简要展示，日视图展示完整记录。
- 不论本人日志是否已提交或保存为草稿，工作视图均不显示日志内容或状态。

## 10. 初步验收场景

### 场景 1：月视图展示长期任务

- **假如** 一项任务从 9 月 18 日持续到 9 月 23 日
- **当** 用户打开 9 月月视图
- **那么** 系统使用跨日期任务条展示该任务，而不是每天创建一条重复记录

### 场景 2：任务跨月

- **假如** 一项任务从 9 月持续到 10 月
- **当** 用户分别查看 9 月和 10 月月视图
- **那么** 两个月视图分别显示同一任务的延续标记

### 场景 3：月视图任务数量过多

- **假如** 某一天关联的任务超过月历单元格展示上限
- **当** 用户打开月视图
- **那么** 系统展示有限数量的任务并显示“还有 N 项”，点击日期后在日视图查看完整内容

### 场景 4：月视图进入日视图

- **假如** 用户正在查看月视图
- **当** 用户点击某个日期
- **那么** 系统切换到该日期的日视图

### 场景 5：周视图展示当天进度

- **假如** 用户在周二将数据库设计任务从 40% 更新到 65%
- **当** 用户查看该周周视图
- **那么** 周二区域展示该任务的“40% → 65%”和对应进展说明

### 场景 6：周视图不重复未更新任务

- **假如** 一项进行中任务在周三没有任何进度或状态更新
- **当** 用户查看该周周视图
- **那么** 系统不在周三重复展示该任务的静态进度

### 场景 7：周视图展示任务状态变化

- **假如** 用户在周五提交任务验收
- **当** 用户查看该周周视图
- **那么** 周五区域展示该任务的“提交验收”状态变化

### 场景 8：周视图不展示日志

- **假如** 用户周一已经提交日志或保存了日志草稿
- **当** 用户查看该周周视图
- **那么** 周一区域只展示任务进度和状态变化，不显示日志摘要、内容、状态或日志跳转入口

### 场景 9：日视图合并同一任务信息

- **假如** 同一任务既覆盖当天，又在当天更新了进度
- **当** 用户查看当日日视图
- **那么** 系统只展示一次该任务，并在任务区域中合并展示当天进展

### 场景 10：日视图展示历史状态

- **假如** 一项任务在 9 月 20 日进度为 40%，之后已经完成
- **当** 用户查看 9 月 20 日日视图
- **那么** 系统展示截至 9 月 20 日的“进行中、40%”，而不是当前最终状态

### 场景 11：日视图查看未来日期

- **假如** 用户查看未来日期
- **当** 该日期存在计划中的任务但尚未产生进度记录
- **那么** 系统展示计划任务，同时显示尚无任务进度记录

### 场景 12：日视图不显示日志

- **假如** 用户当天日志处于草稿状态或已提交
- **当** 用户查看自己的日视图
- **那么** 系统只显示当天任务及任务动态，不显示日志状态、内容或填写入口

### 场景 13：管理者工作视图不显示下属日志

- **假如** 下属当天有已提交日志或草稿
- **当** 管理者查看该下属的周视图或日视图
- **那么** 系统只显示该下属的任务及任务动态，不显示任何日志信息

### 场景 14：管理者尝试修改下属数据

- **假如** 管理者正在查看下属工作视图
- **当** 管理者尝试修改任务或更新进度
- **那么** 系统拒绝操作，并且不产生任何任务数据变更

### 场景 15：越权查看其他组织成员

- **假如** 当前用户是团队长或部门经理
- **当** 该用户尝试查看权限范围之外成员的工作视图
- **那么** 系统拒绝访问，并且不返回该成员的任务数据

### 场景 16：部门经理进入视图时默认查看本人

- **假如** 当前用户是部门经理
- **当** 该用户进入视图 Tab 或清除下属筛选
- **那么** 系统默认显示部门经理本人的工作视图，不自动叠加部门成员任务

### 场景 17：部门经理通过筛选查看本部门员工

- **假如** 本部门普通员工存在任务进度记录
- **当** 部门经理将查看对象筛选为该员工
- **那么** 系统在月、周、日视图中只读展示该员工本人负责或执行的任务及任务动态，不显示日志或其他部门成员数据

### 场景 18：当前周显示未完成任务清单

- **假如** 用户查看当前周，且有尚未完成、已开始或计划在本周开始的本人执行任务
- **当** 用户打开当前周视图
- **那么** 系统显示“本周未完成任务”清单；逐日区域仍只显示当天实际发生的任务进度或状态变化

### 场景 19：历史周不显示未完成任务清单

- **假如** 用户切换到过去的一周
- **当** 系统展示该周视图
- **那么** 系统不显示“本周未完成任务”清单，只显示该周实际发生的任务进度或状态变化

### 场景 20：今日未完成任务与今日进展分开展示

- **假如** 用户查看今天，且有未完成任务，其中部分任务今天没有进度或状态变化
- **当** 用户打开今天的日视图
- **那么** 未完成任务清单包含这些任务；下方进展区域只显示今天实际发生过变化的任务

### 场景 21：筛选下属时同步当前周期规则

- **假如** 管理者在权限范围内筛选某位下属
- **当** 查看对象处于当前周或今天
- **那么** 未完成任务清单和逐日进展都只基于该下属本人任务生成，且保持只读

### 场景 22：历史任务状态按日结束冻结

- **假如** 一项任务在某日结束时处于进行中，之后才被更新或完成
- **当** 用户查看该历史日期
- **那么** 系统仍显示该日结束时冻结的状态和进度，不被之后的变化覆盖
