# 需求 04：月、周、日工作视图

## 文档信息

- 当前版本：v1.0
- 当前状态：月/周/日布局、时间轴与任务动态规则已确认
- 所属阶段：Sprint 0——需求分析与产品设计
- 当前范围：移动端个人工作视图及管理者只读查看下属工作视图
- 关联需求：01-task-creation-and-acceptance.md、03-daily-log-module.md

## 1. 需求目标

工作视图按照任务负责人聚合展示任务。月视图呈现任务从创建到截止的时间跨度；周、日视图采用日期条、全天未完成任务条和 24 小时时间轴布局，呈现负责人任务实际发生的更新、完成提交和验收完成动态。管理者可以按组织权限向下穿透查看下属及下属的下属各自的工作视图。

视图不要求用户重复填写数据，不显示任何日志内容，也不把实际动态解释为计划时段或任务工期。

## 2. 页面入口与通用结构

移动端底部提供“视图”Tab，首次进入默认显示当前月。用户可在月、周、日视图间切换，并可前后切换周期、返回当前周期。三种视图均提供“任务中心”入口；进入任务中心时隐藏底部导航，返回后恢复之前的视图、周期和查看对象。

所有角色默认查看本人视图。具备管理权限的用户可以通过“查看对象”选择权限范围内的下属，包含下属的下属；一次只查看一个责任人的视图，不把整个团队或部门的任务混合叠加。查看对象在月、周、日视图间保持一致，并可随时清除筛选返回本人视图。

视图本身不提供任务编辑、更新、提交、验收或退回操作。月、周、日视图中的所有任务条均可点击进入任务详情；查看本人任务时，详情中的操作遵循需求 01，查看下属任务时详情为只读。

## 3. 数据来源与动态规则

视图只读取正式任务、任务创建时间、截止时间、负责人、二态完成状态，以及任务的文字更新、完成提交和验收完成记录，不复制或单独维护任务数据。

周、日动态记录只包含以下类型：

| 动态类型 | 记录内容 |
| --- | --- |
| 任务更新 | 负责人追加的任务进展说明、发生时间 |
| 完成提交 | 负责人提交完成成果的时间及成果说明 |
| 验收完成 | 直接派发者验收通过的时间及验收说明 |
| 提交并完成 | 负责人同时为创建人时，提交与完成合并后的一条记录 |

任务标题、动态类型和发生时间均须完整展示；更新说明不截断，通过自动换行显示完整内容。动态卡片高度随文字内容纵向扩展，表示一个实际发生的时间点，不表示持续时长。同一天的动态按实际发生小时归入时间轴小时段，并在小时段内按完整发生时间排序。某小时的时间轴行根据该小时最多动态列所需的卡片数量和内容高度自动扩展；该小时所有日期列保持相同行高，确保行对齐，且任何动态卡片都不得越过本小时范围。同一任务多次更新时，每次分别记录。

动态归属按任务负责人，而不是按执行该操作的人：上级验收某项下属负责的任务后，“验收完成”显示在该责任人的视图中，不显示在上级本人的视图中；只有当上级本人也是该任务的负责人时，才会显示在上级本人的视图中。上级向下查看该下属视图时可以看到此记录。

负责人同时为任务创建人时，不产生独立的“验收完成”事件；提交完成成果与任务完成合并显示为一次“提交并完成”。

审批、审批退回、任务取消及普通任务字段编辑不属于本视图动态。视图不读取 DailyLog、日志摘要、草稿或任务与日志的关联数据。

## 4. 工作视图的任务范围与完成状态

本人视图只展示本人作为负责人的正式任务。管理者选择某位下属后，复用同一规则展示该下属作为负责人的任务和这些任务的动态；创建人不是视图筛选条件，管理者不因此看到“该员工创建的任务”清单。

普通任务的完成状态只有“未完成”和“已完成”。任务更新或完成提交不会自动改变完成状态；只有验收通过，或责任人同时为创建人时提交并完成，任务才变为“已完成”。已取消归档的任务不进入当前未完成任务区。

工作视图不展示公司重要事项、公司十大重要任务、个人重点排序、日志、自建学习计划、重复习惯或多人叠加日历。

## 5. 月视图

### 5.1 展示规则

月视图以任务创建日期作为任务条的可见起点，以截止日期作为终点，直观呈现创建与截止日期。该起点表示任务实际创建日期，不代表实际开始执行日期。任务条只展示任务标题和“未完成”或“已完成”状态；状态标签须清晰易读，不在标题前显示圆点。

长跨度任务以连续任务条呈现，不重复生成任务。每个日期最多展示三条任务，超出部分显示该日期准确的“+N项”；点击日期或“+N项”进入该日日视图。所有任务条均可点击进入任务详情。

月视图中历史日期的完成状态按该自然日结束时的状态呈现，不被之后发生的更新覆盖。

### 5.2 月视图示意

| 日期范围 | 任务条 |
| --- | --- |
| 创建日 ━━━━━━━━━ 截止日 | 完成需求评审　未完成 |

任务条在日历中的起止位置表达创建日期和截止日期，不把它描述为计划工期。

## 6. 周视图

周视图参考周历布局，由上至下依次包括：周日期条、全天任务区域、24 小时时间轴。周一至周日七列须在手机可用宽度内同时完整显示，不需要横向滑动；日期列宽度紧凑且均匀，列间距保持轻微留白。日期条按周一至周日排列，每个日期显示星期和日期；点击某日进入对应日视图。

当前周的“全天”区域显示该责任人所有未完成且未取消归档的任务条。任务条可横跨多个日期：统一从本周第一天绘制；截止日期在本周内时延伸到截止日期所在日，否则延伸到周末。条长只用于提示截止日期是否落在本周，不表示任务创建日期、实际开始日期或工期。任务条只显示标题，可点击进入详情。历史周和未来周不显示当前周未完成任务区域。

周日期条与全天任务区域固定在时间轴上方；仅 24 小时时间轴区域纵向滚动，不能横向滚动整周。日期条、全天任务条和下方动态列必须使用同一组等宽日期列，确保动态条落在其发生日期正下方。全天区域下方显示 00:00—23:00 的完整 24 小时时间轴，日期作为横向列、时间作为纵向刻度。任务更新、完成提交、验收完成等真实动态按发生日期放入对应日期列，再归入发生小时；动态条显示完整发生时间、任务标题、动态类型和完整摘要，文字可换行，不因卡片宽度被省略。同一小时内按发生时间排序并纵向堆叠；小时行高度根据该小时所需的卡片数量及内容高度自动拓展，且整行各日期列等高，保证动态卡片不越过小时分界线。动态条仍表示单个时间点而非持续时段。历史日期仅显示真实动态，未来日期不预生成动态。

## 7. 日视图

日视图沿用日期条、全天任务区域和 24 小时时间轴结构。日期条显示所选日期所在周的星期与日期，当前日期突出显示；选择其他日期可在日视图内切换查看。七日日期条紧凑固定且完整显示，不需要横向滑动；全天任务区域也固定在时间轴上方。仅时间轴纵向滚动，动态条位于所选日期对应的单日时间轴中。

仅查看今天时，“全天”区域按任务条列出该责任人当前所有未完成且未取消归档的任务；任务条仅显示任务标题，可点击进入详情。过去日期和未来日期不显示未完成任务区域。

全天区域下方按 00:00—23:00 展示所选日期的完整时间轴，真实发生的任务动态归入对应小时并按发生时间排序；任务卡片展示完整发生时间、任务标题、动态类型和完整摘要，文字可换行且不截断。小时行高度按该小时内卡片数量与内容高度自动拓展，卡片纵向排列且不越过小时分界线。当天没有动态时保留空白时间轴，不生成虚构进展；未来日期不预生成事件条。历史日动态保留其实际发生时间；历史完成状态按对应自然日结束时冻结，后续事件不得改写此前日期的历史结果。日期条与全天任务条保持固定，只有时间轴纵向滚动。

## 8. 管理者向下查看

创始人、部门经理和团队长可按各自组织权限向下穿透查看下属及下属的下属的月、周、日视图。向下查看时，选择某个责任人后，三种视图均只呈现该责任人作为负责人承担的任务，不额外展示由该员工创建但分配给其他人的任务。

管理者查看下属视图时为只读。任务条仍可进入任务详情，但详情不得提供任务变更或审批、验收操作。筛选范围不可越权；月、周、日切换时保持当前查看对象和周期关系。

## 9. 点击与导航规则

- 月视图任务条、周/日未完成任务条、周/日动态任务条均可点击并打开对应任务详情。
- 从下属视图打开的任务详情为只读；从本人视图打开的详情按需求 01 的权限和流程展示。
- 月/周视图点击日期进入对应日视图；点击月历“+N项”进入该日期日视图。
- 三种视图的任务中心入口进入独立任务中心页面；返回时恢复进入前的视图模式、周期及查看对象。
- 工作视图中不提供编辑或处理任务流程的入口。

## 10. 初步验收场景

### 场景 1：月视图呈现创建至截止跨度

- **假如** 一项任务于 10 月 8 日创建，截止日期为 10 月 15 日
- **当** 负责人查看 10 月月视图
- **那么** 日历任务条从 10 月 8 日延伸至 10 月 15 日；起点仅表示创建日期，不表示开始执行日期

### 场景 2：周视图显示负责人进展更新

- **假如** 负责人于周二 10:30 追加任务进展说明
- **当** 负责人或有权限的上级查看该周视图
- **那么** 对应责任人视图显示 10:30 动态卡片，包含任务标题、“任务更新”和完整更新说明；文字可换行，不被截断

### 场景 3：上级验收记录归属责任人视图

- **假如** 上级于周三 16:20 验收通过某项下属负责的任务
- **当** 下属本人或有权限的上级查看该下属的周/日视图
- **那么** 责任人视图显示“验收完成”动态；该记录不显示在上级本人的视图中，除非上级本人也是任务责任人

### 场景 4：责任人为创建人的任务完成

- **假如** 负责人同时是任务创建人并提交完成
- **当** 任务完成记录生成
- **那么** 视图只显示一条“提交并完成”动态，不拆成提交和验收两条

### 场景 5：本周未完成任务

- **假如** 用户查看当前周且承担多项未完成任务
- **当** 打开周视图
- **那么** 日期条显示周一至周日；“全天”区域以可点击任务条列出这些任务，任务条可跨多个日期，截止日在本周内时终止于截止日列、否则延伸至周末；其长度只提示截止日是否在本周，不代表工期

### 场景 6：周视图显示全天任务与 24 小时时间轴

- **假如** 本周任务在周三 14:30 有更新、周五 16:20 被验收完成
- **当** 用户打开周视图
- **那么** 日期条、全天未完成任务条和 00:00—23:00 时间轴按参考周历布局显示；两条动态分别定位在周三 14:30 和周五 16:20 的日期列与时间位置

### 场景 6a：周视图完整显示七天并固定顶部

- **假如** 用户在手机上打开周视图
- **当** 查看整周日期和全天任务
- **那么** 周一至周日七列同时完整显示，不需要横向滑动；日期条和全天任务区域保持固定，只有下方时间轴纵向滚动，且每条动态与顶部对应日期列对齐

### 场景 6b：周视图按小时容纳完整动态

- **假如** 周三 09:00—10:00 有多条动态，且动态标题或说明较长
- **当** 用户查看该周的时间轴
- **那么** 动态卡片完整换行显示并按时间排序；09:00 小时行按卡片数量和内容高度自动增高，各日期列的该小时行保持等高，卡片不越过 10:00 分界线

### 场景 7：今日未完成任务

- **假如** 用户查看今天且承担未完成任务
- **当** 打开日视图
- **那么** 日期条显示所选日所在周的日期，“全天”区域以可点击任务条列出未完成任务，下面显示完整 24 小时时间轴

### 场景 7a：日视图固定日期与全天任务

- **假如** 用户在手机上打开日视图
- **当** 上下滚动查看所选日期的任务动态
- **那么** 七日日期条及全天任务区域保持固定且无需横向滑动，动态仅在下方所选日期的 24 小时时间轴中纵向滚动

### 场景 7b：日视图按小时容纳完整动态

- **假如** 所选日期某小时存在多条动态或较长的动态说明
- **当** 用户查看该小时的时间轴
- **那么** 动态卡片完整换行显示并按发生时间排列，该小时行自动增高以容纳所有卡片，卡片不越过相邻小时分界线

### 场景 8：历史周、历史日与未来日期

- **假如** 用户查看过去或未来周期
- **当** 页面展示周/日视图
- **那么** 不显示当前周/今日未完成任务区域；历史只显示当时真实发生的动态，未来不生成动态

### 场景 9：所有视图任务条均可进入详情

- **假如** 用户点击任一月视图任务条、未完成任务条或动态任务条
- **当** 当前任务属于本人或已选下属
- **那么** 系统打开对应任务详情；查看下属时为只读

### 场景 10：管理者向下穿透

- **假如** 管理者在组织权限范围内选择下属或下属的下属
- **当** 切换月、周、日视图
- **那么** 三个视图均展示所选责任人的任务和动态，不把其他人员任务混合到该视图

### 场景 11：视图不显示日志

- **假如** 本人或下属当天有已提交日志或日志草稿
- **当** 用户查看任一工作视图
- **那么** 页面只显示任务和符合本需求的任务动态，不显示日志状态、内容或摘要

## 11. MVP 展示边界

工作视图仅呈现月度任务创建/截止跨度、周历/日历式全天未完成任务条及 24 小时任务动态时间轴。周视图全天任务条跨度仅提示截止日是否落在当前周；视图不推断工作起始日或实际工期，也不通过日志补充任务进展。所有月份、周次和日期均按任务及动态的实际时间戳计算。
