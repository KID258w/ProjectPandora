# 需求 07：标签系统

## 文档信息

- 当前版本：`v0.7`
- 当前状态：标签颜色可编辑且同步更新既有关联；固定调色板、任务和日志中的标签样式及视图展示规则已确认
- 所属阶段：需求分析与产品设计
- 当前范围：Android App 标签管理、任务与日志的标签关联、工作视图标签标记
- 关联需求：`01-task-creation-and-acceptance.md`、`03-daily-log-module.md`、`04-month-week-day-work-views.md`

## 1. 需求目标

由创始人在 Android App 中管理一套全公司共享的标签，供所有 App 角色在有权填写的日志、创建或编辑任务时选择。任务和日志可以关联多个标签；工作视图中的任务条只显示任务标题，并根据关联标签显示颜色，不显示标签名称或其他任务信息。

标签系统仅属于 Android App 的业务功能，与管理员操作的 Web 端无关。

## 2. 角色与权限

| 角色 | 标签管理 | 任务与日志标签关联 |
| --- | --- | --- |
| 创始人 | 在 App“我的页面”通过“标签管理”按钮进入标签管理中心；可查看、创建、修改启用标签的名称和颜色、删除（停用）标签 | 在本人有权创建或编辑的任务和日志中选择标签 |
| 部门经理 | App“我的页面”不显示标签管理按钮，不可管理标签 | 在本人有权创建或编辑的任务及本人可编辑的日志中选择标签 |
| 团队长 | App“我的页面”不显示标签管理按钮，不可管理标签 | 在本人有权创建或编辑的任务及本人可编辑的日志中选择标签 |
| 普通员工 | App“我的页面”不显示标签管理按钮，不可管理标签 | 在本人有权创建或编辑的任务及本人可编辑的日志中选择标签 |

所有 App 角色都可以查看并选择标签库中的启用标签。标签选择不扩大用户原有的任务创建、任务编辑、日志编辑、组织查看或数据访问权限。

标签管理、标签关联和标签筛选均不出现在 Web 管理端。

## 3. 标签信息与管理

### 3.1 标签信息

MVP 标签包含以下信息：

| 信息 | 规则 |
| --- | --- |
| 名称 | 必填；创始人创建后可修改；名称在启用标签之间全局唯一，停用标签不参与唯一性校验 |
| 颜色 | 创始人创建标签时从系统预设的 10 种颜色中选择；标签启用期间可修改为其他预设颜色，停用后不可修改 |
| 状态 | 系统维护为启用或停用；停用标签仍保留记录和历史关联 |
| 创建/更新时间 | 系统记录，不要求用户填写 |

标签名称使用简短、能概括任务或日志主题的词语。MVP 不增加描述、分类、热度、公开话题等社交平台属性。

标签颜色来自以下固定的 10 色调色板。创始人创建标签时必须选择其中一种；创建和编辑表单用实际颜色样本展示 10 个选项，不能只显示颜色名称或色值。标签数量超过 10 个时允许多个标签使用同一种颜色。创始人可以在标签启用期间修改颜色，但只能改为调色板中的颜色；标签停用后不可修改。颜色保存在标签记录中，停用标签保留停用时的颜色。修改标签颜色后，所有已有任务和日志关联标签及工作视图任务条同步使用新颜色。

### 3.2 创始人管理

只有创始人登录 Android App 后，“我的页面”才显示“标签管理”按钮；点击后进入标签管理中心，可查看标签列表、创建标签、修改启用标签的名称或颜色，以及删除标签。其他 App 角色的“我的页面”不显示该按钮。管理列表只显示启用标签，并以彩色标签块展示名称和对应颜色；已停用标签不在管理中心显示，但保留在数据库中，已有任务和日志仍显示其名称与颜色。创建和编辑启用标签时，表单必须以可见的颜色样本展示全部 10 种预设颜色，供创始人选择。已停用标签不能修改、恢复启用或用于新关联。

创始人执行删除时，系统将标签标记为停用，不物理删除数据库记录，也不解除其已有任务或日志关联。停用是不可逆操作，App 不提供重新启用入口。创始人确认删除前，App 必须显示确认框，说明该标签不能恢复、不能用于新关联，但既有任务和日志关联会保留。

停用标签不出现在任务或日志标签选择器的可选列表中；若历史任务或日志仍关联该标签，任务和日志编辑表单及详情仍显示该历史关联的标签名称，但不标明停用状态。若启用标签与停用标签同名，编辑表单中通过颜色区分二者。用户可以保留既有关联或将其移除；移除后不能重新添加该停用标签。既有关联任务和工作视图仍使用该标签原有颜色。

创始人修改标签名称后，所有既有关联的任务和日志同步显示新名称；修改颜色后，所有既有关联的任务和日志及工作视图任务条同步使用新颜色。修改标签名称或颜色均不改变标签关联关系或任务、日志原有的业务状态。

创始人成功创建、修改或停用标签时，系统同时记录员工 App 操作审计。标签名称、颜色、状态等变更字段的修改前后值可供管理员在员工 App 操作记录详情中核查；不在该页面提供标签管理或恢复操作，具体规则见需求 05。

## 4. 任务与日志中的标签选择

### 4.1 标签选择器

任务创建/编辑表单和日志填写/编辑表单均提供可选的多选标签栏：

- 默认列出标签库中的全部启用标签。
- 提供按名称搜索的筛选栏；输入关键词后筛选标签名称。
- 用户可以选择一个或多个标签；不在选择器内创建、修改或删除标签。
- 停用标签不能新关联。若当前记录已有该历史关联，编辑表单照常显示其标签名称但不标明停用状态；用户可以保留或移除。移除后不能重新添加该停用标签。
- 已关联到任务或日志的标签，以椭圆形色块显示：标签名称位于色块内，背景色使用该标签记录中保存的颜色。此样式用于任务和日志表单中的已选标签及详情页中的关联标签。

标签为可选信息，不改变任务审批、执行、验收、取消、日志提交或日志日期规则。已审批任务仅增删标签不触发重新审批。

### 4.2 标签编辑权限与时机

- **任务**：创建时由创建人选择标签；已有任务的标签只能在需求 01 原有的可编辑任务表单中维护，不新增编辑权限。创建人/直接派发者仅能在任务未完成且原流程允许编辑时修改；审批退回任务由创建人修改并重新提交；下属任务只读视图不能编辑。已完成或已取消归档的任务不能改标签。审批通过后单独增删标签不重新触发审批。
- **日志**：只有作者可以在本人今天、昨天或前天的日志中维护标签，包括已提交日志；管理者对下属日志只读。日期超过近三天窗口后日志冻结，作者也不能修改标签。日期窗口按需求 03 的业务时区自然日计算。
- **停用标签**：若标签已存在于当前记录，编辑表单显示其名称但不标明停用状态；用户不改动时保留原关联。用户将其从记录中移除后，停用标签不再可选，也不能重新关联。

### 4.3 标签详情展示与可见范围

任务详情和日志详情均展示记录当前关联的全部标签，每个标签以椭圆形色块呈现，色块内显示标签名称，背景使用标签记录中保存的颜色。历史关联中的停用标签也照常显示原名称和颜色，不标明停用状态。标签展示沿用任务或日志原有的查看权限。

日志标签与日志正文遵循相同的可见性规则：草稿及其标签仅作者本人可见；已提交日志及其标签对原有权限范围内的查看者可见。标签不扩大管理者查看日志的权限。任务详情中的标签也不扩大任务原有的组织查看权限。

MVP 不增加任务列表标签筛选、日志搜索或日志标签筛选。

## 5. 工作视图标记

- 月、周、日工作视图中的任务条只显示任务标题，不显示标签名称或其他任务信息；任务条颜色依据关联标签。
- 没有关联标签的任务条使用中性灰色。
- 一个任务关联多个标签时，任务条使用当前仍关联的标签中最早添加者的颜色。之后添加的标签不改变任务条颜色；若最早添加的标签被移除，则改用剩余关联标签中最早添加者的颜色。同一标签关联的任务使用该标签相同的颜色。
- 任务颜色不再区分“他人派发”和“本人创建”，也不表达完成状态或跨部门属性。
- 停用标签仍可作为既有关联任务的视图标记；创始人修改启用标签名称后，详情和编辑表单中的关联名称同步更新，颜色不变；工作视图任务条仍只显示任务标题和颜色。

标签标记不改变任务视图原有的数据范围、只读权限、日期规则或动态归属规则。

## 6. MVP 边界

- 标签库全公司共享，由创始人在 Android App 管理。
- 所有 App 角色均可在其有权填写的任务、日志表单中搜索并关联已有启用标签。
- 任务和日志可多选标签；标签选择器不提供标签管理操作。
- Web 管理端不提供标签管理、关联或筛选功能。
- 不增加任务列表标签筛选、日志搜索、热度排序、公开话题或社交分享能力。
- 标签不改变任务、日志原有的业务权限和工作流。

## 7. 初步验收场景

### 场景 1：创始人管理标签

- **假如** 当前用户以创始人身份使用 Android App
- **当** 创始人在“我的页面”点击“标签管理”进入管理中心，并查看、创建、修改名称或删除标签
- **那么** 创建表单以颜色样本展示 10 种预设颜色并要求选择一种；标签记录和启停状态按本需求维护，删除不会解除历史关联

### 场景 1a：其他角色没有标签管理入口

- **假如** 当前用户以部门经理、团队长或普通员工身份使用 Android App
- **当** 用户打开“我的页面”
- **那么** 页面不显示“标签管理”按钮，但用户仍可在有权填写的任务和日志表单中选择启用标签

### 场景 2：其他角色选择但不能管理标签

- **假如** 当前用户是部门经理、团队长或普通员工
- **当** 用户打开有权填写的任务或日志表单
- **那么** 用户可以搜索并多选启用标签，但不能创建、修改或删除标签

### 场景 3：标签选择栏按名称搜索

- **假如** 标签库中存在多个启用标签
- **当** App 用户在任务或日志表单的标签栏输入名称关键词
- **那么** 选择器按标签名称筛选并允许选择匹配的标签

### 场景 4：停用标签保留历史关联

- **假如** 标签已关联任务或日志
- **当** 创始人删除该标签
- **那么** App 先提示删除不可恢复、不可再关联、既有任务和日志仍保留标签；确认后标签记录及既有关联保留，历史记录仍显示名称和颜色

### 场景 5：修改名称并保留颜色

- **假如** 一个标签已关联任务或日志
- **当** 创始人修改该标签名称
- **那么** 所有关联信息同步显示新名称，标签颜色不变；工作视图仍只显示任务标题和颜色

### 场景 5a：修改启用标签颜色并同步更新既有关联

- **假如** 一个启用标签已关联任务或日志
- **当** 创始人将该标签改为另一种预设颜色并保存
- **那么** 所有已有任务和日志关联标签及工作视图任务条都使用新颜色；标签关联关系和业务状态不变

### 场景 6：任务条只显示标题并按标签着色

- **假如** 任务关联了多个标签
- **当** 用户在月、周或日工作视图查看该任务
- **那么** 视图只显示任务标题，不显示标签名称，并使用当前仍关联标签中最早添加者的颜色；任务来源不再使用独立颜色区分

### 场景 7：已审批任务仅变更标签

- **假如** 任务已通过审批
- **当** 有权编辑该任务的用户仅增删标签
- **那么** 标签关联更新，不触发重新审批

### 场景 8：查看已提交日志标签

- **假如** 日志已提交，且查看者原本有权查看该日志
- **当** 查看者打开日志详情
- **那么** 查看者可看到该日志关联标签；草稿标签仍仅作者本人可见

### 场景 9：任务和日志详情展示全部关联标签

- **假如** 当前用户有权查看一项任务或日志
- **当** 用户打开该任务或日志的详情
- **那么** 详情显示该记录关联的全部标签名称；已停用的历史标签不标明停用状态，且不扩大原有查看权限

### 场景 10：Web 管理端无标签入口

- **假如** 系统管理员进入 Web 管理端
- **当** 管理员查看组织、账号或操作记录功能
- **那么** Web 管理端不显示标签管理、标签关联或标签筛选操作

### 场景 11：编辑时处理已停用标签

- **假如** 一项可编辑任务或日志仍关联已停用标签
- **当** 用户打开其编辑表单
- **那么** 表单显示该标签名称但不标明停用状态；用户保留关联时它继续显示，移除后则不能再次关联该标签

### 场景 12：标签编辑服从任务和日志的编辑边界

- **假如** 用户尝试修改任务或日志的标签
- **当** 该任务不符合需求 01 的编辑权限或状态规则，或该日志超出需求 03 规定的本人近三天可编辑窗口、或用户是查看者而非日志作者
- **那么** 用户不能修改标签；任务和日志标签编辑分别遵循各自原有的可编辑权限与时间窗口

### 场景 13：日志和任务详情以标签色块展示关联标签

- **假如** 用户有权查看一项关联了标签的日志或任务
- **当** 用户打开日志或任务详情
- **那么** 每个关联标签以椭圆形色块展示，色块内显示标签名称，背景色取自该标签记录保存的颜色；停用标签仍按原名称和颜色展示，不标明停用状态
