# 需求 09：个人每日事项

## 1. 目标与边界

每日事项是员工为自己安排的个人备忘录。它用于记录和安排个人事项，不是公司任务，不进入“我的任务”、公司任务看版、审批流程或公司工作视图。事项只对创建它的账号可见和可操作；其他员工及 Web 管理端不能查看或管理。每日事项操作不写入员工 App 操作审计或 Web 管理审计。

本需求描述 Android App 的个人每日事项和首页“每日事项”面板。Web 管理端和公司任务接口不在此功能范围内。

## 2. 事项信息与生命周期

每条事项包含：

- **标题**：必填。
- **开始日期、结束日期**：必填，精确到日；起止日期均包含在事项范围内，结束日期不能早于开始日期。
- **说明**：选填，用于记录备忘内容。
- **颜色**：必填，使用标签系统已有的 10 种预设颜色；创建后可以编辑。

每日事项没有完成、未完成、逾期或审批状态。起止日期表示事项覆盖的日期范围，不代表任务进度。第一版不支持按周、月等规则自动重复生成事项；长周期事项通过一条事项的开始日期和结束日期表示。

创建、编辑和删除仅作用于当前登录账号自己的事项。删除操作需要确认；确认后，该事项从个人事项月历、当天事项列表和首页预览中移除。

## 3. 首页面板

首页四大面板之一命名为“每日事项”，替代原“个人十大重点工作”面板。它与“任务看版”是不同数据：任务看版读取公司任务；每日事项读取当前账号自行创建的个人备忘录。

- 首页最多预览 5 条日期范围覆盖今天的个人事项，即 `开始日期 ≤ 今天 ≤ 结束日期`。
- 首页不提供创建按钮；点击“查看全部”进入独立的个人事项月历。
- 没有覆盖今天的事项时显示空状态，不以公司任务或其他内容补齐。
- 首页预览不展示或修改事项的完整说明、日期或颜色配置；完整信息在月历详情浮窗中查看。

## 4. 个人月历

### 4.1 进入和创建

用户从首页“每日事项”卡片进入个人事项月历。月历页提供月份切换和创建入口，首页不提供创建入口。点击月历顶部的年月，可打开快速选择窗口，直接切换年份和月份；窗口样式与正式 App 的年月快速选择保持一致。

用户在月历页创建事项时，表单默认以当前选中的日期作为开始和结束日期；没有选中日期时默认今天。表单提供标题、开始日期、结束日期、选填说明，以及带真实色块预览的 10 种颜色选择。编辑时可以修改以上字段，包括颜色。

### 4.2 月历展示

- 月历仅显示当前登录账号自己的事项。
- 每条事项按起止日期在月历上以任务条形式延展；跨周时按周分段连续显示。任务条使用该事项自己的预设颜色，不使用标签或公司任务颜色。
- 同一天有多条事项且日期格放不下时，日期格显示可容纳的事项条及“+N项”入口。用户点击日期或“+N项”入口，都打开所选日期的事项列表。
- 当天事项列表包含所有日期范围覆盖所选日期的事项，按卡片排列；每张卡片以事项对应颜色作为背景，并显示标题及日期范围。
- 所选日期没有事项时，显示该日期的空状态。

### 4.3 事项详情与操作

- 点击月历任务条，或当天事项列表中的事项卡片，均以浮窗卡片显示事项详情，不导航到新的详情页面。
- 详情浮窗显示标题、起止日期、选填说明和事项颜色，并提供编辑、删除操作。
- 点击编辑进入事项表单，保存后立即更新首页、月历任务条、当天列表和详情。
- 点击删除先显示确认框；用户确认后事项从当前账号的每日事项中移除。取消确认则保留事项。

## 5. 拖动调整日期

- 用户长按月历中的事项任务条并拖到另一个日期，以拖动开始时手指所在的日期作为原日期，以松手位置对应的日期作为目标日期。
- 长按后任务条应明显抬起并跟随手指移动；松手后使用平滑动效落到目标日期位置，恢复普通大小和阴影。
- 系统按原日期与目标日期之间的天数整体平移事项的开始和结束日期，保持事项原有跨度不变，起止日期仍包含在内。
- 拖动到月历左右边缘时自动切换到相邻月份；初次触边立即切换，手指持续停留时继续逐月切换，离开边缘或松手后停止。
- 切换月份时以平滑的横向滑动动画衔接；拖动状态和事项预览保持连续，用户可以继续移动到目标日期再松手。
- 拖动用于整体移动日期范围，不用于缩短或延长事项；修改跨度通过编辑表单完成。
- 拖动完成后，月历、首页预览及日期列表立即显示新日期范围。

## 6. 数据及审计边界

- 每日事项归属于创建账号；任意 App 业务角色都只能访问自己的事项。
- 每日事项使用独立的个人事项数据，不复用公司任务、日志、标签关联或员工操作审计记录。
- 创建、编辑、删除事项不产生 App 操作审计或 Web 管理审计条目；Web 管理端审计页面及接口不包含每日事项数据。
- Demo 原型可以使用本地内存状态演示交互，不代表后端持久化或多设备同步已经实现。

## 7. 验收场景

### 场景 1：首页只显示今天覆盖的本人事项

- **假如** 当前账号有今天正在进行或从今天开始的事项，也有日期范围不覆盖今天的事项
- **当** 用户查看首页
- **那么** “每日事项”只预览日期范围覆盖今天的本人事项，最多五条，不显示其他账号的事项

### 场景 2：跨多日事项显示

- **假如** 用户创建了开始日早于结束日的事项
- **当** 用户查看覆盖其日期范围的月历
- **那么** 每个起止日期（含首尾）对应的日期均显示同一事项的彩色任务条，跨周部分连续延展

### 场景 3：创建表单默认日期和颜色

- **假如** 用户在月历选中某一天并开始创建事项
- **当** 创建表单打开
- **那么** 开始日期和结束日期都默认为所选日期，用户可以选择标题、说明和 10 种预设颜色之一

### 场景 4：日期格事项过多

- **假如** 某日覆盖的事项超过日期格可以显示的数量
- **当** 用户点击日期或该日期的“+N项”入口
- **那么** 系统显示该日全部事项的彩色卡片列表，而不是只显示溢出的几条

### 场景 5：从月历或列表查看详情

- **假如** 某事项显示在月历任务条或当天事项卡片中
- **当** 用户点击任务条或卡片
- **那么** 系统在浮窗卡片中显示事项标题、起止日期和说明，并提供编辑、删除操作

### 场景 6：修改事项内容和颜色

- **假如** 用户正在编辑自己的事项
- **当** 用户修改标题、日期范围、说明或预设颜色并保存
- **那么** 事项更新后在首页和所有涉及日期的月历位置同步显示，日期结束早于开始日期时不保存并提示用户

### 场景 7：确认删除事项

- **假如** 用户在事项详情中点击删除
- **当** 用户取消确认
- **那么** 事项仍保留；当用户确认删除时，事项从个人事项月历、当天列表和首页移除

### 场景 8：长按拖动事项任务条

- **假如** 一条事项覆盖连续多天
- **当** 用户长按任务条并将其从日期 A 拖至日期 B
- **那么** 系统将整个起止日期范围平移相同天数，保持原跨度，不改变颜色、标题和说明

### 场景 9：拖动到月历边缘后切换月份

- **假如** 用户正在月历中拖动一项事项
- **当** 手指进入月历左侧或右侧边缘区域
- **那么** 月历平滑切换到上一个或下一个月，拖动保持进行中，用户可以继续将事项移动到目标日期

### 场景 10：个人事项不进入任务和审计

- **假如** 用户创建、编辑或删除自己的每日事项
- **当** 用户查看公司任务、工作视图、Web 管理审计或 App 操作审计
- **那么** 个人事项不出现在这些模块或记录中，且其他员工不能访问该事项

### 场景 11：不自动重复生成

- **假如** 用户创建一条个人每日事项
- **当** 事项日期经过或进入下一周、下一个月
- **那么** 系统只展示用户创建的这一条日期范围事项，不自动生成重复事项
