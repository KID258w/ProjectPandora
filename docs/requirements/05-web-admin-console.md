# 需求 05：Web 管理端

## 文档信息

- 当前版本：`v0.5`
- 当前状态：Issue2 账号与组织管理规则已确认；具体表单布局由前端设计确定
- 所属阶段：Sprint 0——需求分析与产品设计
- 当前范围：管理员使用的 Web 管理端
- 关联需求：`01-task-creation-and-acceptance.md`、`02-home-four-panels.md`、`03-daily-log-module.md`

## 1. 产品定位与范围

Web 管理端是 Pandora 的系统管理后台，供管理员维护组织、用户账号、角色权限和移动端首页的“公司十大重要事项”。

这里所说管理员“只维护公司十大重要事项”，是指管理员只维护这一类公司级业务内容，不维护或处理业务任务；并不表示 Web 管理端只有重要事项管理。组织、员工信息、账号和角色管理仍保留在 Web 管理端。

```text
移动端 App
→ 创始人、部门经理、团队长和员工处理业务任务、工作日志及工作视图

Web 管理端
→ 管理员维护组织、用户账号、角色权限和公司十大重要事项
```

Web 管理端不提供业务任务或员工工作日志的查看、查询、编辑、导出入口。任务和日志属于移动端业务角色的工作范围；管理员不参与任务派发、执行、进度更新、提交或验收。

当前 Web 端功能范围：

1. 管理员登录与简要工作台
2. 部门和团队管理
3. 用户账号、业务角色及所属组织管理
4. 公司十大重要事项维护
5. 管理员操作记录

## 2. 导航与工作台

```text
Pandora 管理后台

├─ 工作台
├─ 组织与人员
│  ├─ 部门管理
│  ├─ 团队管理
│  ├─ 用户管理
│  └─ 角色与权限
├─ 公司重要事项
└─ 系统管理
   └─ 管理员操作记录
```

只有管理员账号可以登录 Web 管理端。普通员工、团队长、部门经理和创始人使用移动端 App，不因业务角色自动获得 Web 管理权限。管理员账号停用后，不得继续登录或调用 Web 管理接口。

工作台只展示系统管理概况，可以包括启用用户数量、部门数量、团队数量、已发布公司重要事项数量和最近管理员操作记录；不展示任务或日志数量、状态、内容或统计信息。

## 3. 组织与人员管理

### 3.1 部门管理

管理员可以新增、查看和启用或停用部门。部门详情展示名称、说明、启用状态、负责人（没有启用的负责人时显示“无”）、下属团队和成员。部门详情页只允许修改部门名称和说明；负责人和成员信息只读。

部门经理通过员工管理界面设置、撤销或调整，不在部门详情页直接编辑。一个部门最多有一名启用的部门经理，也允许暂时没有启用的部门经理。停用部门前，必须先处理其启用中的下属团队和成员；停用保留部门及其历史记录，不物理删除。

### 3.2 团队管理

管理员可以在指定部门下新增、查看和启用或停用团队。团队详情展示名称、说明、启用状态、所属部门、负责人（没有启用的负责人时显示“无”）和成员。团队详情页只允许修改团队名称和说明；所属部门、负责人和成员信息只读。团队所属部门在创建时指定，创建后不通过团队详情页调整。

团队长通过员工管理界面设置、撤销或调整，不在团队详情页直接编辑。一个团队最多有一名启用的团队长，也允许暂时没有启用的团队长。停用团队前，必须先处理其启用中的成员；停用保留团队及其历史记录，不物理删除。团队管理不提供业务任务派发功能。

### 3.3 用户与角色管理

管理员可以新增业务账号，并在员工管理界面筛选、查看和维护员工的业务身份、部门/团队归属及启用状态。员工列表可按姓名、手机号、业务身份、部门、团队和启用状态筛选；可查看姓名、手机号和部分隐藏的身份证号。

新建业务账号时，Web 表单要求填写姓名、手机号、身份证号、业务身份及对应的部门/团队归属。身份证号为必填。Web 不要求录入初始密码或账号状态：后端生成强随机初始密码并自动启用新账号。创建成功后，Web 通过一次性结果窗口向当前管理员显示登录手机号和初始密码，供其转交员工；关闭窗口后清除密码明文。初始密码不保存在浏览器本地存储、应用日志或管理员操作记录中，创建响应不得缓存。

员工创建后，管理员不能通过 Web 修改员工姓名、手机号、身份证号或密码，也不能重置密码。员工可在 Android App 修改本人姓名、手机号、身份证号和密码；App 不允许修改业务身份、部门/团队归属、直属上级或启用状态。员工在 App 修改手机号后，后续登录使用新手机号；MVP 不要求短信验证码。密码遗失后的找回流程尚未确定。

每人使用一个账号。业务角色包括创始人、部门经理、团队长和普通员工；一个业务账号只配置一个主要业务角色。创始人、部门经理和团队长在该角色之外同时具有员工身份。MVP 不支持同一人同时担任多个部门或团队管理职务。管理员是独立的系统管理角色，MVP 不支持同一账号同时作为 Web 管理员和移动端业务账号。管理员维护组织和角色关系，但不参与业务任务处理。

业务账号仅有一个主要业务身份，身份与部门/团队归属联动校验。部门、团队、员工的启用状态在各自列表中维护；停用对象仍可在管理列表中查看和重新启用，但停用部门、团队和员工不能作为新归属或负责人分配表单的候选项。停用员工立即禁止登录并保留历史记录。

调整负责人时，管理员在员工管理界面先撤销原负责人的身份，再调整其部门/团队归属；原组织可以暂时没有启用负责人。目标组织已有启用负责人时，不得再授予第二个负责人身份。系统不自动指定接任者，也不覆盖现任负责人。直属上级关系由后端依据当前身份和组织归属维护，客户端不直接提交直属上级 ID。负责人空缺期间，受影响员工可以暂时没有直属上级；设置启用的新负责人后，后端重新关联对应下属。

## 4. 公司十大重要事项

管理员根据公司管理层确定的内容，在 Web 端维护移动端首页的“公司十大重要事项”。该内容用于展示公司级重要信息，不是业务任务，不包含负责人、任务进度、父子任务关系或验收信息。

管理员可以新增、编辑、保存草稿、发布或下架事项，手动调整首页展示顺序，按需上传或移除附件，并预览移动端展示效果。不提供置顶功能。草稿不展示给移动端用户；所有移动端用户看到相同的已发布事项。首页最多展示 10 条已发布事项；达到 10 条后，管理员须先下架一条，才能发布新事项。附件保留为可选能力，具体格式和大小限制在实现设计阶段确定。

注意区分：移动端首页的“公司十大重要任务”按需求 02 的规则，从当前用户自己的任务列表生成；它不是管理员维护的全公司任务清单。Web 管理端只维护“公司十大重要事项”，不查看或维护业务任务。

## 5. 管理员操作记录

系统应记录管理员成功执行的部门、团队、用户、角色权限和公司重要事项新增、编辑、启停、发布、下架等管理操作。记录至少包括管理员账号、操作时间、操作模块、操作类型、操作对象和操作结果；涉及内容修改时，记录修改前后内容。MVP 不设置自动清理期限，支持按时间、管理员、模块筛选；不提供数据导出。

管理员操作记录只用于审计 Web 管理操作，不包含业务任务或员工日志内容，也不提供任务或日志查看行为记录，因为 Web 管理端不提供这些数据的查看功能。

操作记录不得保存明文密码或完整身份证号；涉及员工身份证号时不记录完整值。

## 6. 权限汇总

| 数据或功能 | 管理员 Web 权限 |
| --- | --- |
| 部门与团队 | 新增、查看、编辑名称和说明、启用、停用；负责人和成员只读 |
| 用户账号与角色 | 新增、查看、筛选、调整身份/部门/团队、启用、停用；个人资料只读；不提供密码重置 |
| 公司十大重要事项 | 新增、查看、编辑、发布、下架、排序 |
| 管理数据导出 | MVP 不提供 |
| 正式业务任务 | 不提供查看、查询或操作入口 |
| 员工工作日志 | 不提供查看、查询或操作入口 |
| 个人学习计划和习惯 | 不可查看 |

Web 页面导航、页面路由及后端管理接口均不得向管理员暴露业务任务或员工日志数据。直接访问相关地址或接口也应拒绝，并且不返回数据。

## 7. 初步验收场景

### 场景 1：非管理员访问 Web 管理端

- **假如** 当前账号不是管理员，
- **当** 该账号尝试登录 Web 管理端或调用管理接口，
- **那么** 系统拒绝访问。

### 场景 2：管理员新增部门

- **假如** 管理员已登录 Web 管理端并填写合法的部门信息，
- **当** 管理员保存信息，
- **那么** 系统创建部门并记录管理员操作。

### 场景 3：管理员设置团队长

- **假如** 管理员在员工管理界面筛选出一名启用员工，且目标团队没有启用的团队长，
- **当** 管理员将该员工身份调整为该团队的团队长，
- **那么** 后端校验身份与团队归属并更新负责人关系；团队详情显示该负责人。

### 场景 3a：部门或团队详情只读展示负责人和成员

- **假如** 管理员打开部门或团队详情，
- **当** 当前组织有启用负责人或成员，
- **那么** 页面显示相应信息，但只允许编辑组织名称和说明；没有启用负责人时显示“无”。

### 场景 3b：负责人暂时空缺及转移

- **假如** 员工当前是部门经理或团队长，
- **当** 管理员先撤销其负责人身份再调整其组织归属，
- **那么** 原组织可暂时没有负责人；若目标组织已有启用负责人，则系统拒绝再分配第二名负责人，且不会自动替换或指定接任者。

### 场景 4：管理员发布公司重要事项

- **假如** 管理员已填写完整的重要事项内容，
- **当** 管理员发布该事项并将其加入首页展示，
- **那么** 所有移动端用户可以看到该事项，系统记录本次管理操作；草稿对移动端用户不可见。

### 场景 5：已发布事项达到上限

- **假如** 首页已有 10 条已发布的公司重要事项，
- **当** 管理员尝试再发布一条事项，
- **那么** 系统阻止发布并提示先下架一条已发布事项；下架后才可发布新事项。

### 场景 6：Web 端不提供任务和日志查看

- **假如** 系统中存在业务任务和员工日志，
- **当** 管理员使用 Web 管理端，或尝试直接访问任务、日志页面及接口，
- **那么** Web 端没有相应导航入口，页面和接口不展示、不返回任务或日志数据。

### 场景 7：管理员停用用户

- **假如** 管理员准备停用一个员工账号，
- **当** 管理员执行停用操作，
- **那么** 系统禁止该用户继续登录并保留历史记录；若该用户是负责人，组织允许暂时没有启用负责人，且其受影响下属的直属上级关系置空。

### 场景 8：停用仍有启用中下级对象的组织

- **假如** 部门仍有启用中的团队或成员，或团队仍有启用中的成员，
- **当** 管理员尝试停用该部门或团队，
- **那么** 系统提示先调整或停用相关下级对象，不直接停用该组织。

### 场景 8a：停用对象不出现在组织调整候选项

- **假如** 管理员正在员工管理界面调整另一名员工的身份或部门/团队归属，
- **当** 系统加载可选组织和负责人，
- **那么** 已停用的部门、团队和员工不会作为候选项出现。

### 场景 8b：员工创建成功后交付一次性初始密码

- **假如** 管理员填写有效的手机号、必填身份证号、姓名、业务身份及组织信息，
- **当** 后端创建业务账号成功，
- **那么** 账号自动启用，Web 显示手机号和本次响应中的初始密码；后续读取、日志和审计记录不包含明文密码。

### 场景 8c：员工在 App 修改手机号

- **假如** 已登录员工提交一个未被使用的新手机号，
- **当** App 个人资料修改成功，
- **那么** 后续登录使用新手机号；App 登录请求仍将手机号放入 `username` 字段。

### 场景 9：记录管理员操作

- **假如** 管理员成功修改组织、账号、角色或公司重要事项，
- **当** 修改完成，
- **那么** 系统记录操作人、时间、对象、操作类型、结果及适用的修改前后内容。

## 8. 已确认规则与实现阶段细节

本需求的 MVP 功能范围和主要业务规则已确认：管理员维护组织、员工账号和角色，以及公司十大重要事项；Web 端不查看或处理业务任务和员工日志；公司重要事项手动排序、无置顶、草稿不展示且最多 10 条已发布事项；MVP 不提供数据导出。

菜单、表单和详情的具体视觉布局由前端设计确定；字段规则、编辑边界、负责人约束和账号交付方式按本文验收。手机号校验格式的技术细节及公司重要事项附件的具体格式和大小限制在实现设计阶段确定。
