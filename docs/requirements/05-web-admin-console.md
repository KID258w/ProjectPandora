- 当前版本：`v0.5`

## 1. 产品定位与范围

Web 管理端是 Pandora 的系统管理后台，供管理员维护组织、用户账号、角色权限和移动端首页的“事件纪”。

这里所说管理员“只维护事件纪”，是指管理员只维护这一类公司级业务内容，不维护或处理业务任务；并不表示 Web 管理端只有重要事项管理。组织、员工信息、账号和角色管理仍保留在 Web 管理端。

```text
移动端 App
→ 创始人、部门经理、团队长和员工处理业务任务、工作日志及工作视图

Web 管理端
→ 管理员维护组织、用户账号、角色权限和事件纪
```

Web 管理端不提供业务任务或员工工作日志的常规浏览、查询、编辑或导出入口。任务和日志属于移动端业务角色的工作范围；管理员不参与任务派发、执行、进度更新、提交或验收。例外是独立的“员工 App 操作记录”审计页面：管理员可查看成功操作的元数据及任务、日志等业务字段的历史修改值，用于人工核查和找回；这不开放常规任务/日志列表或详情浏览。

当前 Web 端功能范围：

1. 管理员登录与简要工作台
2. 部门和团队管理
3. 用户账号、业务角色及所属组织管理
4. 事件纪维护
5. 管理员操作记录
6. 员工 App 操作记录

## 2. 导航与工作台

```text
Pandora 管理后台

├─ 工作台
├─ 组织与人员
│  ├─ 部门管理
│  ├─ 团队管理
│  ├─ 用户管理
│  └─ 角色与权限
├─ 事件纪
└─ 系统管理
   ├─ 管理员操作记录
   └─ 员工 App 操作记录
```

只有管理员账号可以登录 Web 管理端。普通员工、团队长、部门经理和创始人使用移动端 App，不因业务角色自动获得 Web 管理权限。管理员账号停用后，不得继续登录或调用 Web 管理接口。

工作台只展示系统管理概况，可以包括启用用户数量、部门数量、团队数量、已发布公司重要事项数量和最近管理员操作记录；不展示任务或日志数量、状态、内容或统计信息。

## 3. 组织与人员管理

### 3.1 部门管理

管理员可以新增、查看和启用或停用部门。部门详情展示名称、说明、启用状态、负责人（没有启用的负责人时显示“无”）、下属团队和成员。部门详情页只允许修改部门名称和说明；负责人和成员信息只读。部门因仍有启用的下属团队或成员而无法停用时，界面应明确显示阻塞类型、数量和对象名称，便于管理员先处理相关对象。

部门经理通过员工管理界面设置、撤销或调整，不在部门详情页直接编辑。一个部门最多有一名启用的部门经理，也允许暂时没有启用的部门经理。停用部门前，必须先处理其启用中的下属团队和成员；停用保留部门及其历史记录，不物理删除。

### 3.2 团队管理

管理员可以在指定部门下新增、查看和启用或停用团队。团队详情展示名称、说明、启用状态、所属部门、负责人（没有启用的负责人时显示“无”）和成员。团队详情页只允许修改团队名称和说明；所属部门、负责人和成员信息只读。团队所属部门在创建时指定，创建后不通过团队详情页调整。

团队长通过员工管理界面设置、撤销或调整，不在团队详情页直接编辑。一个团队最多有一名启用的团队长，也允许暂时没有启用的团队长。停用团队前，必须先处理其启用中的成员；若因此无法停用，界面应明确显示启用成员数量及对象名称。停用保留团队及其历史记录，不物理删除。重新启用团队时，其所属部门必须处于启用状态。团队管理不提供业务任务派发功能。

### 3.3 用户与角色管理

管理员可以新增业务账号，并在员工管理界面筛选、查看和维护员工的业务身份、部门/团队归属及启用状态。员工列表可按姓名、手机号、业务身份、部门、团队和启用状态筛选；可查看姓名、手机号和部分隐藏的身份证号，并通过列表开关直接启用或停用员工。

新建业务账号时，Web 表单要求填写姓名、手机号、身份证号、业务身份及对应的部门/团队归属。身份证号为必填。Web 不要求录入初始密码或账号状态：后端生成强随机初始密码并自动启用新账号。创建成功后，Web 通过一次性结果窗口向当前管理员显示登录手机号和初始密码，供其转交员工；关闭窗口后清除密码明文。初始密码不保存在浏览器本地存储、应用日志或管理员操作记录中，创建响应不得缓存。

员工创建后，管理员不能通过 Web 修改员工姓名、手机号、身份证号、头像或密码，也不能重置密码。员工可在 Android App 修改本人姓名、手机号、身份证号和密码；App 不允许修改业务身份、部门/团队归属、直属上级或启用状态。姓名和身份证号在同一个个人资料编辑表单中提交，可在一次保存中同时修改；二者是独立字段，不自动联动，只修改其中一项时不要求另一项也变化。姓名和身份证号通过同一次 API 更新时必须作为一个原子操作，校验失败时均不保存。员工在 App 修改手机号后，后续登录使用新手机号；MVP 不要求短信验证码。密码遗失后的找回流程尚未确定。

员工可在 App 的“我的”或个人资料页点击头像更换本人头像。App 将所选图片上传到后端，头像二进制保存在该账号的数据库记录中；同一账号在其它设备登录时也读取该头像。头像属于员工本人资料，不提供 Web 管理端编辑入口。支持 JPEG、PNG、WebP，文件不超过 5 MiB，宽高各不超过 4096 且总像素不超过 1600 万；未设置头像时显示姓名首字。

App“我的”页面的个人信息卡右侧显示任职天数，按员工账号创建日期计算；账号创建当天算第 1 天，并按 `Asia/Shanghai` 自然日计算。账号创建日期由当前用户资料接口返回。

每人使用一个账号。业务角色包括创始人、部门经理、团队长和普通员工；一个业务账号只配置一个主要业务角色。创始人、部门经理和团队长在该角色之外同时具有员工身份。MVP 不支持同一人同时担任多个部门或团队管理职务。管理员是独立的系统管理角色，MVP 不支持同一账号同时作为 Web 管理员和移动端业务账号。管理员维护组织和角色关系，但不参与业务任务处理。

业务账号仅有一个主要业务身份，身份与部门/团队归属联动校验。部门、团队、员工的启用状态在各自列表中维护；停用对象仍可在管理列表中查看和重新启用，但停用部门、团队和员工不能作为新归属或负责人分配表单的候选项。停用员工立即禁止登录并保留历史记录。

公司最多有一名启用创始人，一个部门最多有一名启用部门经理，一个团队最多有一名启用团队长；每一级都允许暂时没有启用负责人。调整负责人时，管理员在员工管理界面先撤销原负责人的身份或停用原账号，再调整负责人的身份/状态；目标组织已有启用负责人时，不得再授予第二个负责人身份。系统不自动指定接任者，也不覆盖现任负责人。负责人唯一性冲突时，Web 应通过错误弹窗完整显示后端返回的原因。直属上级关系由后端依据当前身份和组织归属维护，客户端不直接提交直属上级 ID。负责人空缺期间，受影响员工可以暂时没有直属上级；新的负责人创建、启用或任命后，后端重新关联对应直接下属。

新建、启用或转入普通员工/负责人岗位时，所需的直属负责人必须已启用；任命负责人填补本级空缺时，候选人自身所需的直属负责人仍须启用。负责人链缺失时，受影响组织范围内的业务账号暂时不能使用 App：公司没有启用创始人时限制全部业务账号；部门没有启用经理时限制该部门及下属团队；团队没有启用团队长时限制该团队。该限制由后端登录、令牌刷新及 App API 鉴权共同执行；员工数据库启用状态和管理员 Web 访问不因此批量改变。负责人链恢复后，后端恢复直属关系，App 访问随之恢复。身份证号在所有业务账号中全局唯一，账号停用后仍保留该号码；后端比较和保存身份证号前去除首尾空格并将字母统一为大写，避免同一号码因末位 `x/X` 大小写不同而重复录入。

## 4. 事件纪

Web 管理端导航和页面统一显示为“事件纪”。管理员根据公司管理层确定的内容维护移动端首页事件；底层仍沿用现有公司事项资源和接口名称。该内容用于展示公司级重要信息，不是业务任务，不包含负责人、任务进度、父子任务关系或验收信息。

管理员可以新增、编辑、保存草稿、发布或下架事项，手动调整已发布事项的首页展示顺序，并预览移动端展示效果。不提供置顶功能。只有已发布事项显示序号并提供排序控件；草稿和已下线事项不显示序号或排序控件，也不参与已发布事项排序。草稿不展示给移动端用户；所有移动端用户看到相同的已发布事项。首页最多展示 10 条已发布事项；达到 10 条后，管理员须先下架一条，才能发布新事项。当前需求不包括公司重要事项附件的上传、管理或下载；后端已有附件模型和接口暂予保留，不作为当前 Web/App 流程的验收要求。后续若增加公司事项详情页或附件上传、下载，应另行确认需求与访问规则；任务相关附件应在任务模块单独设计。

注意区分：移动端首页的“任务看版”按需求 02 的规则，从当前用户自己的任务列表生成；它不是管理员维护的全公司任务清单。Web 管理端只维护“事件纪”，不查看或维护业务任务。

## 5. 管理员操作记录

系统应记录管理员成功执行的部门、团队、用户、角色权限和公司重要事项新增、编辑、启停、发布、下架等管理操作。记录至少包括管理员账号、操作时间、操作模块、操作类型、操作对象和操作结果；涉及内容修改时，记录修改前后内容。MVP 不设置自动清理期限，支持按时间、管理员、模块筛选；不提供数据导出。

管理员操作记录只用于审计 Web 管理操作，不包含业务任务或员工日志内容，也不提供任务或日志查看行为记录，因为 Web 管理端不提供这些数据的查看功能。

操作记录不得保存明文密码或完整身份证号；涉及员工身份证号时不记录完整值。

## 5.1 员工 App 操作记录

员工 App 操作记录用于在员工离职或交接前发生大量任务、日志等业务数据修改时，帮助管理员查明操作并参考历史值人工处理。它与“管理员操作记录”分开保存和展示；不提供一键恢复、常规任务/日志浏览或编辑，也不提供导出。

系统只记录成功登录及成功的状态变更操作，包括员工个人资料、头像和密码变更，任务创建/编辑/重新提交/审批/退回/进度更新/完成提交/验收/取消，日志创建/保存/提交/编辑/评论，以及创始人的标签创建/修改/停用。只读查看、失败登录或失败写操作、个人重点工作排序、通知已读不记录。

记录至少包含操作者、操作发生时间、模块、动作、目标对象、操作结果和变更字段。操作者姓名、业务职位、部门和团队按操作发生时保存快照；目标对象保存可识别的名称或日期。任务、日志及相关业务内容的变更需保存变更字段的修改前后值；创建操作没有修改前值。涉及标签关联时，修改前后的快照包含标签 ID 和操作当时的名称；负责人变更快照包含负责人 ID 和操作当时的姓名。Web 详情按“名称（ID）”展示，不能只显示数字 ID；旧记录只有数字 ID 时，尽可能依据保留的标签或员工记录补出名称。列表只显示摘要，点击记录后才显示修改前后值，供管理员人工处理。

密码、完整身份证号、认证令牌和头像二进制不得保存到操作记录。操作记录详情属于受限审计数据，仅管理员可访问。留存期限尚待确定；MVP 建议暂不自动清理。

## 6. 权限汇总

| 数据或功能 | 管理员 Web 权限 |
| --- | --- |
| 部门与团队 | 新增、查看、编辑名称和说明、启用、停用；负责人和成员只读 |
| 用户账号与角色 | 新增、查看、筛选、调整身份/部门/团队、启用、停用；个人资料只读；不提供密码重置 |
| 事件纪 | 新增、查看、编辑、发布、下架、排序 |
| 员工 App 操作记录 | 只读查看成功操作摘要及任务/日志等业务字段的历史修改值；仅管理员可访问，不提供一键恢复或导出 |
| 管理数据导出 | MVP 不提供 |
| 常规业务任务 | 不提供查看、查询或操作入口；仅可在员工 App 操作记录中查看限定的变更历史 |
| 常规员工工作日志 | 不提供查看、查询或操作入口；仅可在员工 App 操作记录中查看限定的变更历史 |
| 个人学习计划和习惯 | 不可查看 |

除“员工 App 操作记录”页面及其专用审计 API 外，Web 页面导航、页面路由及后端管理接口不得向管理员暴露业务任务或员工日志数据。该审计例外仅返回成功操作的限定元数据和变更前后快照，不提供常规任务/日志列表或详情 API；直接访问未授权业务接口仍应拒绝并且不返回数据。

## 7. 初步验收场景

### 场景 1：非管理员访问 Web 管理端

- **假如** 当前账号不是管理员，
- **当** 该账号尝试登录 Web 管理端或调用管理接口，
- **那么** 系统拒绝访问。

### 场景 2：管理员新增部门

- **假如** 管理员已登录 Web 管理端并填写合法的部门信息，
- **当** 管理员保存信息，
- **那么** 系统创建部门并记录管理员操作。

### 场景 3：管理员设置团队长

- **假如** 管理员在员工管理界面筛选出一名启用员工，且目标团队没有启用的团队长，
- **当** 管理员将该员工身份调整为该团队的团队长，
- **那么** 后端校验身份与团队归属并更新负责人关系；团队详情显示该负责人。

### 场景 3a：部门或团队详情只读展示负责人和成员

- **假如** 管理员打开部门或团队详情，
- **当** 当前组织有启用负责人或成员，
- **那么** 页面显示相应信息，但只允许编辑组织名称和说明；没有启用负责人时显示“无”。

### 场景 3b：负责人暂时空缺及转移

- **假如** 员工当前是创始人、部门经理或团队长，
- **当** 管理员停用或撤销其负责人身份，
- **那么** 公司/部门/团队可暂时没有启用负责人，其直接下属的直属上级置空；系统不会自动替换或指定接任者。

### 场景 3c：负责人恢复及 App 暂停

- **假如** 创始人、部门经理或团队长空缺导致业务用户的负责人链不完整，
- **当** 这些用户尝试登录、刷新令牌或访问 App 接口，
- **那么** 后端拒绝 App 访问；管理员仍可在 Web 端补齐负责人。
- **当** 管理员创建、启用或任命有效负责人，
- **那么** 后端重建其直接下属关系，受影响用户的 App 访问恢复。

### 场景 3d：转入负责人空缺的组织

- **假如** 管理员准备将普通员工转入或启用到一个缺少必需直属负责人的组织，
- **当** 管理员提交调整，
- **那么** 后端拒绝本次调整并提示先补齐负责人；用于填补该组织负责人空缺的任命操作可以继续。

### 场景 4：管理员发布公司重要事项

- **假如** 管理员已填写完整的重要事项内容，
- **当** 管理员发布该事项并将其加入首页展示，
- **那么** 所有移动端用户可以看到该事项，系统记录本次管理操作；草稿对移动端用户不可见。

### 场景 5：已发布事项达到上限

- **假如** 首页已有 10 条已发布的公司重要事项，
- **当** 管理员尝试再发布一条事项，
- **那么** 系统阻止发布并提示先下架一条已发布事项；下架后才可发布新事项。

### 场景 6：Web 端不提供任务和日志查看

- **假如** 系统中存在业务任务和员工日志，
- **当** 管理员尝试访问常规任务/日志列表、详情或写接口，
- **那么** 后端拒绝请求且不返回业务数据；员工 App 操作记录页面只返回有权限的历史变更快照。

### 场景 7：管理员停用用户

- **假如** 管理员准备停用一个员工账号，
- **当** 管理员执行停用操作，
- **那么** 系统禁止该用户继续登录并保留历史记录；若该用户是负责人，组织允许暂时没有启用负责人，且其受影响下属的直属上级关系置空。

### 场景 8：停用仍有启用中下级对象的组织

- **假如** 部门仍有启用中的团队或成员，或团队仍有启用中的成员，
- **当** 管理员尝试停用该部门或团队，
- **那么** 系统拒绝停用，并明确列出仍启用的下属团队/成员类别、数量和对象名称，提示管理员先处理这些对象。

### 场景 8e：停用部门下的团队不能启用

- **假如** 团队所属部门处于停用状态，
- **当** 管理员尝试重新启用该团队，
- **那么** 系统拒绝启用并提示先启用所属部门。

### 场景 8a：停用对象不出现在组织调整候选项

- **假如** 管理员正在员工管理界面调整另一名员工的身份或部门/团队归属，
- **当** 系统加载可选组织和负责人，
- **那么** 已停用的部门、团队和员工不会作为候选项出现。

### 场景 8b：员工创建成功后交付一次性初始密码

- **假如** 管理员填写有效的手机号、必填身份证号、姓名、业务身份及组织信息，
- **当** 后端创建业务账号成功，
- **那么** 账号自动启用，Web 显示手机号和本次响应中的初始密码；后续读取、日志和审计记录不包含明文密码。

### 场景 8c：员工在 App 修改手机号

- **假如** 已登录员工提交一个未被使用的新手机号，
- **当** App 个人资料修改成功，
- **那么** App 清除本机登录会话并返回登录页，提示员工使用新手机号重新登录；App 登录请求仍将手机号放入 `username` 字段。

### 场景 8f：员工在 App 修改密码后重新登录

- **假如** 已登录员工提交正确的当前密码和有效的新密码，
- **当** 密码修改成功，
- **那么** App 清除本机登录会话并返回登录页，提示员工使用新密码重新登录。

### 场景 8g：拒绝重复负责人并显示原因

- **假如** 公司、部门或团队已经有一名启用负责人，
- **当** 管理员在新建或调整员工时再次分配相同范围的负责人身份，
- **那么** 后端拒绝写入，现有负责人保持不变，Web 通过错误弹窗显示具体冲突原因。

### 场景 8d：员工在 App 一次更新姓名和身份证号

- **假如** 员工在 App 的同一个个人资料编辑表单中修改姓名和身份证号，
- **当** 员工提交保存，
- **那么** 后端在同一次更新中保存两项资料；两项不自动联动，员工也可以只修改其中一项；若任一项校验失败，两项均不保存。

### 场景 8h：员工更换头像并在另一台设备查看

- **假如** 员工已登录 App 并选择一张符合限制的头像图片，
- **当** 员工点击头像并确认更换，
- **那么** 图片被上传并保存到当前账号的数据库资料中；该员工在另一台设备登录后也能看到同一头像。

### 场景 9：记录管理员操作

- **假如** 管理员成功修改组织、账号、角色或公司重要事项，
- **当** 修改完成，
- **那么** 系统记录操作人、时间、对象、操作类型、结果及适用的修改前后内容。

### 场景 10：管理员核查员工 App 操作并人工找回数据

- **假如** 员工在 App 中成功修改了任务或日志，
- **当** 管理员打开员工 App 操作记录并查看该条记录详情，
- **那么** 列表显示全局最新记录及对象名称/日期和变更字段；详情显示该次变更允许保留的修改前后值，管理员可据此人工处理，但页面不提供一键恢复。

### 场景 11：员工 App 操作记录的范围与敏感信息

- **假如** 员工成功登录或执行受支持的 App 写操作，
- **当** 系统记录本次操作，
- **那么** 它保存操作时的操作者身份快照及业务字段变更前后值；失败操作、只读访问、个人重点排序和通知已读不记录，密码和完整身份证号不进入审计快照。

### 场景 12：非管理员请求员工 App 操作记录

- **假如** 当前请求者不是 Web 管理员，
- **当** 其请求员工 App 操作记录页面或 API，
- **那么** 系统拒绝访问且不返回任何审计内容。

## 8. 已确认规则与实现阶段细节

本需求的 MVP 功能范围和主要业务规则已确认：管理员维护组织、员工账号和角色，以及事件纪；Web 端不提供常规业务任务和员工日志的查看或处理，但可通过独立的员工 App 操作记录审计页读取限定的变更前后值以便人工找回；公司重要事项手动排序、无置顶、草稿不展示且最多 10 条已发布事项；MVP 不提供数据导出。

菜单、表单和详情的具体视觉布局由前端设计确定；字段规则、编辑边界、负责人约束和账号交付方式按本文验收。手机号校验格式的技术细节在实现设计阶段确定。公司事项附件不属于当前 Web/App 流程；后端已有附件接口保留，未来若启用附件流程，再另行确定文件格式、大小限制和访问规则。
