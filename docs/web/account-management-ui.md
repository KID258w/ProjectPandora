# 管理员登录与账号管理界面

## 1. 范围与接口阶段

本文件记录 Issue #6 的 Web 两阶段交付：PR2 的管理端界面，以及 PR5 对接后端后的交互；并记录本次 Issue #1 遗留修复。当前管理员认证、部门、团队和业务用户列表/创建均调用 Django API，不再使用本地演示记录。API 请求与响应契约以 [`docs/backend/account-provisioning.md`](../backend/account-provisioning.md) 和后端 Swagger 为准。

Web 只允许管理员账号登录。管理员由后端初始化，不提供自助注册。所有业务请求由后端重新检查身份、账号状态、组织归属和上级关系；前端校验只用于及时提示，不能替代后端授权。

## 2. 页面和登录流程

访问 `/` 会进入 `/login`。登录页提交 `POST /api/v1/admin/auth/token/`，成功后保存 access/refresh 令牌并请求 `GET /api/v1/admin/me/` 验证管理员会话，然后进入 `/dashboard`。无令牌时受保护的管理路由会返回登录页。管理布局显示当前管理员姓名/账号。

请求遇到 401 时使用 `POST /api/v1/admin/auth/token/refresh/` 更新 access 并重试原请求；刷新失败会清除两个令牌并返回登录入口。退出会清除本地令牌。管理员登录失败、网络错误和 API 字段错误会在页面展示后端消息。

## 3. 组织和账号管理

### 部门

- `GET /api/v1/admin/departments/` 读取部门；`POST` 创建部门。
- 列表分页加载所有结果，展示名称、ID、说明、团队数、成员数和可从业务用户推导的启用部门经理。
- 部门名称必填且最多 100 字，提交时也由后端检查唯一性；创建成功后重新读取部门、团队和用户数据。

### 团队

- `GET /api/v1/admin/teams/` 读取团队；按部门过滤时带 `department_id`；`POST` 创建团队。
- 创建时必须选择已存在部门。团队名称最多 100 字且在同一部门内唯一；归属校验由后端执行。
- 团队列表根据服务端用户结果显示负责人和成员数。创建成功后刷新数据。

### 业务用户

- `GET /api/v1/admin/users/` 读取业务用户（包括停用账号）；`POST` 录入业务用户。
- 可按姓名/手机号搜索、按身份和启用状态筛选；列表显示手机号和脱敏身份证号，不显示完整身份证号。
- 创建表单必填姓名、手机号和身份证号。手机号同时作为 App 登录手机号；表单不提供密码和启用状态输入。
- 创建成功后显示后端返回的一次性初始密码和登录手机号。关闭结果窗口后清除密码，不写入浏览器存储；新账号由后端自动启用。
- 先选身份，再显示所需组织字段。部门/团队选项来自 API；选择团队长或员工时，团队列表只包含所选部门的团队。

| 身份 | 部门 | 团队 | 直属上级 |
| --- | --- | --- | --- |
| 创始人 | 不需要 | 不需要 | 无 |
| 部门经理 | 必选 | 不需要 | 后端自动关联启用中的创始人 |
| 团队长 | 必选 | 必选且属于该部门 | 后端自动关联该部门经理 |
| 普通员工 | 必选 | 必选且属于该部门 | 后端自动关联该团队长 |

表单不会发送 `password`、`is_active`、`manager_id`、`account_type`、`is_staff` 或 `is_superuser`。每个有效部门只允许一个启用经理、每团队只允许一个启用团队长，创始人也只能有一个启用账号；录入上级尚未就绪、重复手机号或团队部门不匹配均由服务端校验并显示错误。用户创建成功后列表重新从 API 获取，以展示后端生成的 ID、身份和直属上级。

## 4. 统一请求处理

- Axios base URL 使用 `VITE_API_BASE_URL`（默认 `http://127.0.0.1:8000`），请求路径由服务封装追加 `/api/v1`。
- 所有成功数据从统一 envelope 的 `data` 字段读取；错误优先显示字段详情，再显示服务端 `message`。
- 列表以 `page_size=100` 逐页加载至 `count` 完整，支持超过一页的组织和用户数据。
- 本阶段不实现组织/账号更新、删除、停用、密码重置、分页控件、管理员注册或 Django 运维后台。

## 6. 本地联调

启动后端并完成迁移、初始化管理员后，再在 `web/` 启动 Vite。必要时在 `.env.local` 设置 `VITE_API_BASE_URL` 为浏览器可访问的 Django 地址。若前后端不在同一主机或端口，请将 Vite 来源加入后端 `CORS_ALLOWED_ORIGINS`，并配置对应 `DJANGO_ALLOWED_HOSTS`。接口路径和错误结构可在后端 `/api/docs/` 查看。

构建：`npm ci && npm run build`。PR5 联调需使用有效管理员账号，验证错误密码、部门/团队创建、四种身份录入及后端组织/直属上级校验；实际测试结果应记录在 PR 描述中，不能把本机结果表述为 GitHub CI 通过。
