# 管理员登录与账号管理界面

## 1. 文档目的与阶段范围

本文说明 Issue #6 的 Web 界面阶段（PR 2）：管理员登录、部门管理、团队管理和业务用户录入。当前界面使用前端内存中的演示数据，用于评审页面顺序、字段和交互；本阶段不调用后端、不持久化数据，也不代表认证或权限控制已经生效。接口路径和请求响应以 PR 4 合入并在 Swagger 确认的契约为准，Web 接口联调属于 PR 5。

本页面按 PIXEL v1.1 的业务身份与组织关系设计。管理员通过 Web 管理端维护组织和业务账号；创始人、部门经理、团队长和普通员工是移动端业务身份。一个业务账号只选择一种主要身份。

## 2. 页面顺序

```text
管理员登录
  └─ 工作台
      └─ 组织与人员
          ├─ 部门管理
          ├─ 团队管理
          └─ 用户管理 / 录入员工
```

左侧导航继续展示已有工作台与后续管理模块的占位入口。Issue #6 的本阶段只实现登录和组织、业务用户这三类管理页面；角色权限配置页、公司重要事项和操作审计不属于 PR 2 的完成范围。

## 3. 页面与主要交互

### 3.1 管理员登录

- 输入管理员账号和密码，空值时显示表单校验信息。
- 点击登录后进入管理工作台，并提示当前是界面评审模式。
- 管理员账号由后端初始化，不提供管理员自助注册。
- 当前按钮不验证凭据、不获取令牌，也不建立真实登录会话；认证接入由 PR 5 配合后端接口完成。

### 3.2 部门管理

- 部门列表展示名称、编号、部门经理、团队数、成员数、状态和说明。
- “新建部门”表单要求填写部门名称，可填写说明；演示状态下会校验必填、长度及重复名称。
- 演示数据根据已录入的部门经理业务账号计算部门负责人显示。负责人关联及数据持久化将在后端接口接入后生效。

### 3.3 团队管理

- 团队列表展示团队名称、编号、所属部门、团队长、成员数、状态和说明。
- 可按部门筛选；“新建团队”必须选择有效部门并填写团队名称，可填写说明。
- 演示状态下，同一部门下不允许创建同名团队。业务账号中的团队长身份用于展示对应团队负责人。

### 3.4 用户管理与录入员工

- 列表可按姓名或登录账号搜索，并按业务身份、启用状态筛选。
- 录入表单包含姓名、登录账号、初始密码、业务身份和账号状态。登录账号要求唯一；密码仅在表单输入时存在，不写入演示数据。
- 先选业务身份，再显示相应组织字段：

| 业务身份 | 部门 | 团队 | 直属上级规则 |
| --- | --- | --- | --- |
| 创始人 | 不显示 | 不显示 | 无直属上级 |
| 部门经理 | 必选 | 不显示 | 后端自动关联创始人 |
| 团队长 | 必选 | 必选，且属于所选部门 | 后端自动关联该部门经理 |
| 普通员工 | 必选 | 必选，且属于所选部门 | 后端自动关联该团队长 |

- 表单不允许手动指定直属上级。选择部门后，团队选择器只展示该部门下启用中的团队；切换部门会清除不再匹配的团队选择。
- 演示校验覆盖重复登录账号、组织必填、团队与部门归属匹配，以及每部门一名启用经理、每团队一名启用团队长。服务端仍必须重新校验这些规则。
- 创建后记录只添加到当前页面的内存演示数据；刷新页面会恢复初始样例。账号真实创建和登录能力要等 PR 4 后端与 PR 5 联调。

## 5. 界面评审与运行

在 `web/` 安装依赖后运行 `npm run dev`，打开 Vite 显示的本机地址。可从 `/login` 开始，使用任意非空账号和密码查看静态登录流程，再通过左侧导航检查部门、团队和用户页面。表单新增仅影响当前页面会话中的演示数据，不会写入服务器。

构建检查使用 `npm ci` 和 `npm run build`。接口联调开始前，应先确认 PR 4 的管理员登录、部门、团队、业务用户接口契约，再把演示数据替换成 Axios 请求，并补充真实令牌生命周期、登录错误处理和服务端校验提示。
